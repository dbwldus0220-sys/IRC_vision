# 23:37:09 녹화 시작 자세 실패 분석

## 직접 원인

녹화 10초·15초 화면과 23:37:12 실행 로그에서 다음 오류를 확인했다.

`[STARTUP POSE] ERROR: startup pose name is ambiguous: 오뒤412`

현재 시작 자세 로더는 전체 카탈로그에서 이름이 오뒤412인 프레임을 찾고, 같은 이름의 모든 관절 각도가 동일해야 승인한다. 25개 프레임은 일치하지만 우복귀 모션의 마지막 프레임 1개가 달랐다.

| 모터 ID | 기존 시작 자세 | 우복귀 종료 자세 |
| --- | --- | --- |
| 17 | -24° | -26° |
| 19 | 67° | 68.115234375° |

직전 카메라45도 수정에서 우복귀 프레임 이름의 (90도)를 제거하면서 서로 다른 자세가 동일한 오뒤412 이름을 갖게 된 것이 원인이다. 카메라 각도를 고친 것 자체가 아니라 프레임 이름 충돌이 시작을 막았다. 이는 해당 수정에서 놓친 부작용이다. 완료 허용오차 5°와 무관하게 시작 자세의 동일 이름 검사는 정확한 각도 일치를 요구한다.

뒤이어 나온 `production controller/configuration is unavailable` 오류는 시작 자세 로딩 실패로 target_angles가 비어 생성자가 차단한 결과다. 이번 실행의 이 메시지만으로 모터 컨트롤러 고장이라고 판단하면 안 된다. 화면의 Ground head=N/A도 시작 자세 로더와 별개다.

## 수정

찐라인복귀우회전45도(4회)의 마지막 프레임 이름과 end_pose만 `오뒤412(우복귀45도)`로 구분했다. 모터 각도·토크·프레임 ID·시간·반복·완료 허용오차 및 다른 모션은 모두 보존했다. 시작 자세 로더의 안전 검사를 우회하거나 기존 시작 자세의 관절값을 바꾸지 않았다.

## 검증

- 실제 C++ startup_pose_catalog.cpp를 사용하는 읽기 전용 검사: 수정 전 동일한 ambiguous 오류 재현, 수정 후 23개 각도 로딩 성공.
- 기존 C++ 자세 로더 테스트 3개 통과.
- 우복귀 카메라45도/몸 관절 보존, 런타임 시작 자세 충돌 검사 2개 통과.
- 83개 모션 alias 및 모터 ID 0~22 검사 통과.
- 실제 모터에 접근하거나 로봇 실행을 재시작하지 않았다.

## 별도로 확인된 초기화 실패

직전 23:36:29 및 23:36:52 실행은 `ROBOT_MOTION_RUNTIME_INITIALIZATION_FAILED: DYNAMIXEL Torque OFF verification failed`로 종료됐다. 이는 모터 토크 OFF 명령/상태 읽기 확인 실패이며, 전원·케이블·통신·장치 상태 등 중 무엇이 원인인지는 해당 ROS 오류 한 줄만으로 특정할 수 없다. 이번 녹화의 실행은 그 단계를 지나 Time-based profiles ready for all motors를 출력한 뒤 시작 자세 이름 충돌에서 막혔다. 따라서 이름 충돌은 해결했지만 간헐적 모터 통신 문제까지 해결됐다고 단정하지 않는다.

이번 실행 로그의 Motion position tolerance check는 DISABLED다. JSON의 5° 값과 실행 시 검사 활성화 여부는 서로 다른 설정이다.
