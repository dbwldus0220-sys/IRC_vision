`line_recovery_left_4`는 `유라인복귀좌`, `line_recovery_right_4`는

각각 1/2/3/4다. 첨부 파일의 프레임·토크·시간·배속을 유지하고 런타임 정책인
완료 허용 오차 5°와 모터 4·5의 18°·−18°를 적용했다.
전체 83개 중 15개를 교체했고, 나머지 68개와 꽃게 진입 준비 모션은 보존했다.
원본 발췌, 변경 전 catalog/alias, 교체 목록은
`artifacts/20261003_catalog5_yu_motion_update/`에 보관한다.

검증: 원본 비교·정책 검사 50개, C++ catalog/core/driver 검사 39개 통과.
bridge와 과거 catalog 검사는 수정 전후 모두 480개 통과·59개 기존 실패이며,

전진 반복, 미세 전진→준비→꽃게 연결, 좌측 라인복귀 6회 후 균형을 확인한다.

## 2026-10-03 골대 중앙 정렬의 90px / 140px 구간

Depth Z가 0.39~0.47m인 최종 정렬에서는 백보드 Offset X로 동작을 선택한다.

| Offset X | 동작 |
| --- | --- |
| −140px 미만 | 제자리 좌회전 1회 |
| −140px 이상, −90px 미만 | 왼옆꽃게 |
| −90px 이상, +90px 이하 | 정렬 완료, 나머지 슛 조건 확인 |
| +90px 초과, +140px 이하 | 오른옆꽃게 |
| +140px 초과 | 제자리 우회전 2회 |

영상 분석기와 planner/controller의 슛 중앙 허용 범위를 모두 ±90px로 맞췄다.
큰 오차의 회전 방향은 bearing이 아니라 Offset X 부호로 결정한다. 회전은 기존
`GOAL_CAMERA90_TURN_RIGHT_2` / `GOAL_CAMERA90_TURN_LEFT_1` alias를 사용한다.
회전 성공 후 기존 1초 정지를 거쳐, 정지 이후 촬영된 새 프레임에서 계속 큰 오차가
남으면 같은 회전 묶음을 반복한다. 실행 중에는 중복 명령을 보내지 않는다.
한 번에 ±90px 안으로 들어오면 꽃게걸음을 거치지 않고 정렬 완료로 판단한다.

슛 거리 밖에서는 기존 거리·방향각 기반 접근/후진 판단을 유지한다. 검출 확인,
최신 영상, 공 보유, 슛 전 독립된 1초 정지와 기존 실패/안전 잠금도 유지한다.
모션 JSON의 관절각·토크·배속·반복 수는 이번 변경에서 수정하지 않았다.

검증: 골대 분석·planner·node·bridge·슛 정지·골대 유실·새 반복 시나리오 1,547개 통과.
±90px/±140px 경계, bearing과 픽셀 부호 불일치, 좌우 각각 세 묶음 연속 회전,
1초 정지 중 명령 차단, 지연 프레임 거부, 꽃게/슛 전환을 확인했다.
추가 미션 흐름 검사는 34개 통과, 이전 기록과 동일한 기존 실패 6개가 남는다.
실기 구동은 하지 않았다. 근거리 제자리 회전은 몸의 방향과 Depth Z도 바꿀 수 있으므로,
시뮬레이션에서 반복 회전과 보정 전환을 먼저 확인하고 실물 균형을 확인한다.

## 2026-10-03 골대 미세 전진 뒤 왼옆꽃게 준비 모션

골대에서 직전 완료 모션이 `goal_camera_90_fine_forward_1`~`4`이면,
왼옆꽃게 명령은 `goal_fine_to_default` → 1초 정지 → `goal_camera_90_crab_left`
순서로 실행한다. 준비 모션이 성공해야 정지 시간을 시작하며, 실패·타임아웃·취소 시
꽃게걸음을 실행하지 않는다. 준비와 정지 구간도 기존 원자적 실행 잠금으로 보호한다.
연속 꽃게걸음에는 준비를 반복하지 않으며, 우측 준비 모션과 픽업 경로는 유지한다.

`goal_fine_to_default`의 `찐미세오뒤에서기본자세`는 사용자가 제공한
`robot_motions(4).json`에서 교체했다. 마지막 프레임의 모터 13은 −48°에서 −45°,
모터 14는 48.251953125°에서 45.251953125°로 바뀐다. 같은 alias를 사용하는
슛 준비에도 새 자세가 적용된다. runtime 정책에 따라 허용 오차 5°와 모터 4·5의
18°·−18°를 적용하고, 나머지 값은 첨부 모션 그대로 유지한다. 원본과 변경 전
catalog는 `artifacts/20261003_goal_left_crab_prepare/`에 보관했다.

검증: bridge 430개, 슛 정지 14개, catalog 정책 및 부분 교체 검사 9개 통과.
83개 모션의 형식과 alias 연결 검사도 통과했다. 실제 로봇은 구동하지 않았다.
시뮬레이션에서 준비 완료 뒤 1초 정지와 왼옆꽃게 연결을 먼저 확인하고,
교체된 마지막 자세에서 슛 준비로 이어지는 동작도 확인한다.

## 2026-10-03 라인 검출 중 지면각 무효 시 작은 제자리 회전

일반 `AUTO`/`LINE_TRACK` 및 픽업 뒤 `LINE_TRACK_AFTER_PICKUP`에서 라인이
검출됐지만 점 부족·유효점 부족·전방 간격 부족·피팅 미수렴으로 지면각을 계산하지
못하면, 마지막으로 신뢰할 수 있게 관측한 라인 쪽으로 작은 제자리 회전을 실행한다.
우측은 `LINE_HEADING_TURN_RIGHT_2`, 좌측은 `LINE_HEADING_TURN_LEFT_1`이며,
기존 `post_ball_line_turn_right_2`/`post_ball_line_turn_left_1` alias를 재사용한다.
각 모션의 보정표상 회전각은 15°다. 보이는 가까운 라인 점의 좌우 위치를 우선하고,
그 점이 없으면 기존 offset 기반 방향 기억을 사용한다. 방향을 모르면 대기한다.

`POST_BALL_LINE_ALIGN`에서는 화면의 라인 위치보다 픽업 종료 방향을 우선한다.
첫 번째 pickup 종료의 우회전 방향이면 `POST_BALL_LINE_TURN_RIGHT_2`,
두 번째 pickup 종료의 좌회전 방향이면 `POST_BALL_LINE_TURN_LEFT_1`을 실행한다.
각 회전 묶음 전후에 기존 1초 정지를 유지한다. 회전 완료·정지 이후 촬영된 새 프레임을
확인해 여전히 같은 지면각 무효 상태이면 반복하고, 정상 3점 이상 지면각이 유효해지면
기존 주행/픽업 후 라인 주행으로 돌아간다. 동작 실행 중 다음 회전을 예약하지 않는다.

이 경로는 앞선 두 점 보조의 총 2회 제한을 사용하지 않는다. 정상 피팅으로 회복하거나
현재 입력/실행 조건이 무효해질 때까지 작은 회전 묶음 단위로 재판단한다. 지면각이
무효인 라인을 두 점 임시 지면각으로 승격하여 전진시키는 이전 보조 경로는 이 입력에
적용하지 않는다. analyzer의 정상 최소 3점 조건과 원시 후보 출력은 유지한다.

수신 시각뿐 아니라 촬영 시각도 검사한다. 최신 영상 유실, 미래/오래된 촬영, 낮은 품질,
보정 파라미터 오류 또는 수치 계산 오류를 회전으로 덮어쓰지 않는다. 복구 중 새 프레임이
없으면 픽업 후 기존의 더 큰 미검출 탐색 회전으로 전환하지 않는다. 복구 모션 실패는
방향이 바뀌어도 추가 복구 회전을 막고, 최신 정상 3점 피팅이 확인되어야 해제한다.
기존 안전 잠금과 TIMEOUT 복구 조건도 유지한다.

명령 `source_command`의 `invalid_ground_recovery`, `direction_source`,
`ground_fit_reason`에서 복구 여부·방향 근거·피팅 실패 원인을 확인할 수 있다.
`direction_source`는 일반 주행의 `last_seen_line` 또는 픽업 직후의 `pickup_exit_turn`이다.
모션 JSON, 관절 목표각, 토크, 배속 및 완료 허용 오차는 변경하지 않았다.

검증: 복구·기존 두 점/코너·입력 갱신·node·bridge·슛 정지 테스트 901개 통과.
mission phase flow 및 hurdle positioning은 343개 통과, 변경 전과 동일한 기존 실패
20개가 남는다. 새 회귀 실패는 없다. 첫 번째/두 번째 pickup 방향, 3묶음 이상 반복,
정상 피팅 시 복구 취소, 실행 잠금, 정지 뒤 촬영 경계, 지연된 정상 피팅의 재사용 방지,
실패 후 반대 방향/미검출 탐색 우회 금지를 확인했다. 실기 구동은 하지 않았다.
회전 누적으로 몸의 방향이 계속 바뀔 수 있으므로 시뮬레이션에서 먼저 순서를 확인하고,
실물에서는 공을 든 상태의 균형과 라인 재획득 여부를 확인한다.

## 2026-10-02 슛 전 1초 정지와 슛 허용 조건 분리

슛 전 자세 안정 시간 `SHOT_PRE_MOTION_SETTLE_SEC`를 3초에서 1초로 줄였다.
`goal_stationary_since`는 골대 검출이나 SHOT 후보의 연속 유지 시간과 독립적으로
실행기가 정지한 시간을 기록한다. 일시적인 미검출·확인 대기·거리 경계 변화만으로
이미 정지한 시간을 초기화하지 않는다. 현재의 유효한 SHOT 판단과 기존 공 보유
검사를 통과해야만 이 시간 조건을 검사하므로, 정지 시간이 지났다고 슛을 예약하거나
과거의 슛 허용 결과를 재사용하지 않는다.

모션 발행·RUNNING·실행기 active·시작 준비 미완료 상태는 정지 기록을 지운다.
성공 완료 시점부터 다시 계산하며, 실패 완료는 기존 시간을 버리고 이후 정지 관측부터
새로 계산한다. 모션 후 기존 1초 대기도 정지 시간에 포함하지만, 대기 완료 후 새 관측을
요구하는 기존 검사는 유지한다. 실행기 active 상태가 미확인인 경우 슛을 허용하지 않는다.
이는 실행기 상태에 따른 정지 시간이며 IMU로 자세 흔들림이 사라졌음을 측정한 값은 아니다.
`/motion/decision_debug`의 `shot_settle`에 요구 시간과 누적 정지 시간을 기록한다.

골대 보정 기준은 그대로다. Depth Z가 0.47m보다 멀면 방향 보정을 먼저 검토하지만,
좌우 모두 최소 보정각이 15°이고 오차를 넘지 않는 모션만 선택하므로 15° 미만에서는
전진 판단으로 내려간다. 0.39~0.47m에서는 백보드 중심 오차가 +70px 초과일 때 우측,
−70px 미만일 때 좌측 꽃게걸음을 선택하며 근거리 방향각은 이 선택을 바꾸지 않는다.
21:57 녹화의 약 135초(0.70m, −2.4°), 139초(0.48m, +5.0°),
145초(0.46m, +9.4°) 화면 수치는 이 동작을 설명한다. 화면 수치는 동작 발행에 사용된
프레임과 동기화되지 않으므로 각 명령의 정확한 원시 입력을 복원한 결과는 아니다.
저장된 실행 기록에는 22:00:07에 `GOAL_CAMERA90_TURN_LEFT_1` 성공도 있다.

검증: 노드·슛 정지·골대 planner·bridge 789개, 골대 회전/꽃게걸음 조건 69개 통과.
mission phase flow와 hurdle positioning은 343개 통과, 기존 실패 20개가 남는다.

## 2026-09-29 WAIT 중 입력 갱신과 미세 전진 전 정지

일반 WAIT는 `_info_callback`이 받은 최신 입력과 수신 시각을 저장하고, 매 판단 주기에

코너 기억·공/허들 진입 예약은 일반 입력 갱신과 별개로 의도적으로 유지되는 상태다.
화면의 최근 명령이나 debug의 마지막 선택은 판단을 쉬는 동안 이전 값일 수 있다.

미세 전진에는 `FINE_FORWARD_PRE_MOTION_SETTLE_SEC=1.0`을 적용한다.

픽업 체크포인트의 미세 전진 및 미세 전진을 포함한 GO 진입이 대상이다.

대기를 초기화한다. 같은 후보가 1초 유지되면 그 시점의 유효한 입력으로 명령을 보낸다.
픽업 체크포인트에서는 기존 PICKUP 잠금을 유지한 상태에서 이 대기가 진행된다.

모션을 새로 발행하거나 실행 중이면 시간을 지우고, 성공 완료 후 다시 계산한다.

## 2026-10-01 지면각 주행과 코너 보조 거리 검사

`line_heading_source` 기본값은 `ground`다. 일반 라인 주행과 복귀 방향은 유효한

`ground` 모드는 유효한 지면 투영이 필수다. 진단 메시지에 선택한 `heading_source`,

실제 일반 라인 명령의 모드를 표시한다.

새 모션의 관절각·프레임·시간·토크·반복·재생 속도는 첨부 파일을 유지하고,
완료 허용 오차만 기존 정책인 5°를 적용한다. 일반 LINE LOST는 좌 3회·우 5회로 첫 탐색을 하고 아래 단계별 한도를 적용한다.
라인 제자리 회전 전후에는 1초 정지하며 RECOVER에는 별도 정지 시간을 넣지 않는다.
변경 기록과 백업은 `artifacts/catalog26_shot_update_manifest.json`,
`artifacts/catalog26_shot_update_backup/`에 보관한다.

### 현재 라인 복귀 흐름과 골대 기준

- 기본 라인 주행은 새 라인의 위치·방향·품질로 전진, RECOVER, 제자리 회전을 선택한다.
  일반 LOST 탐색은 마지막으로 보인 쪽으로 좌 3회 / 우 5회부터 회전하며, 매 회전 전에
  1초 정지한다. 완료 후 1초 대기와 새 영상에서도 LOST면 다시 탐색한다. RECOVER는 별도 정지 없이
  좌/우 4회 모션을 실행하고, 완료 후 새 영상에서 여전히 필요하면 반복한다.
- 픽업은 고정 시퀀스를 완료한 즉시 `POST_BALL_LINE_ALIGN`으로 간다.
  필요한 추가 좌·우 정렬은 유지하며, 회전 전/후 각각 1초 정지하고 새 영상으로 확인한다.
  이 정렬 단계도 첫 탐색 좌 3회 / 우 5회, 추가·반대 탐색 좌 1회 / 우 2회를 사용한다.
  정렬 완료 후 일반 라인 판단으로 10초 주행한다. 첫 라인 모션 RUNNING부터 시간을 세며
  보정·대기도 포함한다. 10초가 지나고 실행 중 모션이 끝나면 공 보유 확인 시 카메라90도
  전환을 거쳐 골대 접근으로 가고, 미보유·미확인은 골대를 건너뛴다.
- 슛 성공 후 1초 정지 → 첫 골 우회전 / 두 번째 골 좌회전의 고정 퇴장 모션 →
  1초 정지 → 새 영상으로 일반 라인 판단을 적용한다. 자동 흐름에서 골 이후 전용
  `POST_SHOT_LINE_ALIGN`과 고정 전진 단계는 사용하지 않는다.
- 골대 정렬 범위는 **Offset X -70~+70px / Depth Z 0.39~0.47m**, 양 끝 포함이다.
  기존 검출·득점 확정 및 공 보유 검사는 유지한다. 0.47m 초과에서는 접근하고,
  범위 안에서 좌우를 맞춘 뒤 `찐골넣기`를 실행한다.
- 0.39m 미만의 `GOAL_CAMERA90_BACKWARD_1`은 `goal_camera_90_backward_1` alias를
  통해 `찐후진실전(1회)`를 실행한다.
- 코너 `LEFT`/`RIGHT`는 각각 `찐라인복귀좌회전45도(4회)` /
  `찐라인복귀우회전45 도(4회)`를 실행한다. 완료 후 새 라인 관측으로 일반 주행을 계속한다.

### 이전 카탈로그 25 적용

카탈로그 25 적용 당시 `robot_motions(25).json`의 72개 모션을 반영했다. 대응하는 기존 모션 71개는 `찐` 이름과 원본 데이터로 교체했고, 새 전진 모션 1개를 추가했다. 사용자 요청으로 새 파일에 없는 기존 45개와 관련 alias 20개를 삭제하여 최종 72개만 유지한다. 완료 허용 오차는 5°다. 남은 alias ID는 유지하고 대상 이름만 변경했다. 삭제된 모션을 요청하는 기존 제어 분기는 실행할 수 없으며 다른 모션으로 대체하지 않는다. 아래 이전 설명의 모션명은 접두사 변경 전 표기일 수 있으므로 실제 이름은 `motion_aliases.yaml`을 기준으로 확인한다.

라인 기본 전진은 `찐전진45(6회)`, 공 일반 접근은 `찐전진45(4회)`, 골대 일반 접근은 `찐전진90(4회)/(6회)`다. 카메라 전환과 이탈 회전 및 라인복귀 일부는 이름 외에 관절각·시간도 바뀌었으므로 실기 전 시뮬레이션에서 자세 연결을 확인해야 한다. 전체 삭제 목록과 변경 내용은 [적용 보고서](../../artifacts/20260926_catalog25_migration.md)를 참고한다.

`mission_control`은 STEP의 비전 결과를 action으로 결정하고, 그 action을 C++
motion executor 요청으로 연결하는 ROS 2 패키지다. 모든 기능을 하나의
`main.cpp`로 합치지 않으며 `full_system.launch.py`를 안전한 개발 환경의 공식
실행 진입점으로 사용한다.

## 공식 실행 구조

```text
step/yolo26_detector
  -> step/unified_vision_node
  -> mission_control/motion_decision_node
  -> mission_control/motion_command_bridge_node
  -> irc_step_motion_executor/sdk_motion_executor
```

실제 모터 제어를 소유할 수 있는 노드는 `sdk_motion_executor` 하나뿐이다. 같은
ROS graph에서 Python executor나 다른 motor executor를 동시에 실행하면 안 된다.

## 모듈 책임

- `step`
  - 카메라 입력을 처리하고 비전 결과를 생성한다.
  - 모터와 RobotMotionPlayer SDK에 직접 접근하지 않는다.
- `mission_control/motion_decision_node`
  - 비전 결과를 바탕으로 수행할 action을 결정한다.
  - SDK `motion_id`를 직접 실행하지 않고 bridge에 action을 전달한다.
- `mission_control/motion_command_bridge_node`
  - 지원되는 action을 현재 catalog의 motion alias로 변환한다.
  - `request_id`, command/event ID와 executor status의 상관관계를 관리한다.
  - 모터나 외부 SDK에 직접 접근하지 않는다.
- `irc_step_motion_executor/sdk_motion_executor`
  - 실제 SDK 실행의 유일한 소유자다.
  - hardware enable과 torque approval 정책을 검증한다.
  - 실행 상태와 오류를 `/motion/executor/status`로 반환한다.

현재 bridge는 `STRAIGHT`를 `line_forward_6`, `APPROACH`를 `forward`, `PICKUP_NOW`를 `pickup`,
`GO`를 `hurdle`로만 연결한다. 짧은 전진·회전·SHOT처럼 실물 검증된 SDK motion이
없는 action은 executor로 전송하지 않고 `/motion/status`에 `UNSUPPORTED`를
발행한다.

## 공식 실행 명령

안전한 개발 실행은 simulated backend만 사용한다.

```bash
ros2 launch mission_control full_system.launch.py \
  enable_camera:=false display:=false
```

이 launch는 다음 값을 코드에서 고정한다.

- `backend_type=simulated`
- `enable_robot_hardware=false`
- `explicit_torque_approval=false`

향후 실물 실행의 진입점은 아래 파일이다. 아직 완성된 실물 실행 명령이나 실제
값 예시는 제공하지 않는다.

```text
ros2 launch mission_control full_system_robot.launch.py ...
```

`full_system_robot.launch.py`도 기본적으로 camera와 hardware를 비활성화하고,
torque 승인을 부여하지 않는다. 실물 실행 전에는 다음 항목을 모두 별도 안전
절차에서 검토하고 명시해야 한다.

- 승인된 SDK-enabled 빌드
- 기존 파일인 `motion_json_path`
- 승인된 `robot_device_path`
- 승인된 양의 `robot_baud_rate`
- 완전하고 중복 없는 `robot_motor_ids` 정수 배열
- `enable_robot_hardware=true`에 대한 별도 승인
- `explicit_torque_approval=true`에 대한 독립적인 torque 승인
- 로봇 지지, 비상정지 및 시뮬레이션 선행 검증

`enable_robot_hardware=false`인 기본 상태에서는 SDK runtime이나 Dynamixel 객체를
생성해서는 안 된다. 설정 validation 성공 또한 motion-ready를 의미하지 않는다.

## 백보드 정렬과 득점 (2026-09-20)

- 골대 안의 백보드를 우선하고, 없으면 단독 백보드를 사용한다. 골대만으로는
  추종하지 않는다. 중심축은 공과 같은 화면 중앙 +96px다.
- 백보드 깊이 검출·추적 상한은 **2.0m**다. 1.5~2.0m에서도 유효한 깊이를
  전달하며, 더 가까운 거리도 계속 검출한다. 골대 제어 범위도 **2.0m 이내**로
  설정하여 공 집기 → 추가 라인 정렬 → 일반 라인 판단으로 10초 주행 → 카메라90도
  전환 이후 아래 거리표로 접근한다.
- 득점 조건은 보정된 `offset_x_px`가 **-70~+70px**, `depth_m`이
  **0.39~0.47m**인 경우다. 양 끝값을 포함하며 기존 검출·깊이·득점 확정과
  공 잡기 확인 조건은 유지한다. 조건을 통과하면 **슛 직전 3초 정지** 후
  `goal_shot` → `찐골넣기`을 실행한다. 대기 중 조건이 깨지거나 관측이 오래되면
  대기를 취소하고, 조건을 다시 충족한 시점부터 3초를 센다. 제자리 회전 완료 후
  1초 대기와는 별도로 적용한다.
- 0.47m 초과~2.0m에서는 꽃게걸음 없이 제자리 회전으로 방향을 보정한다.
  우측 오차는 기존대로 15° 이상이면 회전한다. 좌측은 골대 전용 기준으로
  15° 이하는 회전하지 않고, 15° 초과~45° 이하는 1회, 45° 초과부터는
  기존 횟수 구간을 사용한다. 회전하지 않는 범위에서는 좌우 픽셀 위치가
  중앙 범위를 벗어나도 거리별 전진을 이어간다.
  0.39~0.47m에서는 제자리 회전보다 픽셀 기준을 우선하며, -70px 미만이면
  왼쪽 게걸음, +70px 초과이면 오른쪽 게걸음으로 맞춘다.
- 카메라90도 전환은 모션 성공 완료 후 추가 정지 없이 새 골대 관측으로 판단한다.
  골대 일반 전진은 즉시 새 관측을 요구하며, 미세전진·꽃게·후진은 1초 정지 후 새 관측을 요구한다.
  제자리 회전 성공 후에는 1초 정지하고, 정지 중 관측은 폐기한 뒤 새 영상으로 판단한다.
- 실행기는 `post_ball_camera_90` 성공부터 `goal_shot` 성공까지 카메라90도를
  유지한다. 이 구간의 모든 모션에서 머리 모터 ID 0의 목표각을 **1.0°**로
  덮어쓴다. 이는 현재 JSON의 카메라90도 자세에 해당하는 모터각이며,
  `찐미세오뒤에서기본자세`와 `찐골넣기` 마지막 프레임에도 적용한다.
  기존 공 추적용 카메라0도 덮어쓰기는 이 구간에서 활성화하지 않는다.
  골넣기 실패·시간 초과 시에는 재시도를 위해 유지하며, 정상 완료·유효한 모션 취소·
  새 픽업 시작 시 해제한다. 해제 자체가 카메라 복귀 동작을 만들지는 않으므로,
  이후 실행하는 모션의 머리 목표각을 따른다. 실행기 재시작 시 유지 상태는 초기화된다.
  기본 설정은 `goal_head_override_enabled=true`, `goal_head_override_deg=1.0`이며,
  heartbeat의 `goal_head_override_active`로 적용 상태를 확인할 수 있다.
- `SHOT` 명령 전에는 일반 정지 설정과 별도로 항상 3초 정지한다.
  이번 골대 접근에서 `GOAL_CAMERA90_FINE_FORWARD_1~4`가 성공했고 좌우 꽃게걸음은
  한 번도 성공하지 않았다면, `SHOT`을 `미세오뒤에서기본자세` → 완료 후 2초 정지
  → `찐골넣기` 순서로 실행한다. 기존 명령 전 3초 정지는 자세 전환 전에 유지된다.
  꽃게걸음을 사용했거나 미세전진 이력이 없으면 기존 골넣기 모션을 바로 실행한다.
  자세 전환과 2초 정지 중에는 다른 명령을 끼워 넣지 않으며, 전환 실패·시간 초과·취소 시
  골넣기로 진행하지 않는다. 자세 전환 성공을 득점 성공으로 보고하지 않는다.
  이력은 새 픽업 시작, 카메라90도 전환 성공, 골넣기 성공 시 초기화한다.
- 접근 판단은 `ground_distance_m`이 아닌 **백보드 `depth_m`(Depth Z)**를 사용한다.
  목표 중심은 0.43m이며 허용 범위는 0.39~0.47m다. 다음 표의 거리는 목표까지의
  차이가 아니라 현재 측정한 Depth Z다. 실행 완료 후 다시 측정하여 다음 모션을 고른다.

  | Depth Z (mm) | 사진의 명령 | 실제 모션 | 골대 실행 명령 |
  | --- | --- | --- | --- |
  | 1280 < Z ≤ 2000 | `STRAIGHT` | 찐전진90(6회) | `GOAL_CAMERA_90_FORWARD` |
  | 850 < Z ≤ 1280 | `STRAIGHT_4` | 찐전진90(4회) | `GOAL_CAMERA_90_FORWARD_2` |
  | 500 < Z ≤ 850 | `STRAIGHT_0` | 찐미세90도-4(3회) | `GOAL_CAMERA90_FINE_FORWARD_3` |
  | 470 < Z ≤ 500 | `STRAIGHT_0` | 찐미세90도-4(1회) | `GOAL_CAMERA90_FINE_FORWARD_1` |
  | 390 ≤ Z ≤ 470 | 정렬·슈팅 | 중앙 정렬 및 득점 안정 확인 | 게걸음 / 대기 / SHOT |
  | Z < 390 | 후진 1회 | 찐후진실전(1회) | `GOAL_CAMERA90_BACKWARD_1` |

  2.0m 밖에서는 기존처럼 골대 접근 모션을 요청하지 않는다.
  후진 성공 후 1초 정지하고 새 백보드 깊이로 다시 판단한다. 여전히 0.39m 미만이면
  한 번 더 후진하며, 0.39~0.47m이면 좌우 정렬·득점 확인으로 넘어간다.
  0.47m를 넘으면 위 전진 거리표를 적용한다. 골대 카메라90도 유지도 후진 중 적용된다.
  정렬·슈팅 구간 폭이 8cm이므로, 시뮬레이션에서 경계 동작을 먼저 확인한 뒤
  실물 지지 상태에서 전진·후진 이동량과 왕복 반복 여부를 확인한다.

- 요청 표에서 같은 `STRAIGHT_0`가 미세전진 3회와 1회를 가리키므로, 실행 명령은 모션별로
  구분한다. LINE/BALL의 기존 STRAIGHT 매핑은 유지한다.
- `Downloads/robot_motions-1(3).json`의 `미세45도-4`, `미세0도-4`, `미세90도-4`
  및 골대용 1~4회 모션을 런타임에 등록했다. 기본 45도/0도 모션은 원본의 5회 반복이다.
  첨부 파일의 `미세90도-4(2회/3회/4회)`에는 공잡기 프레임이 잘못 들어 있어,
  정상 `미세90도-4(1회)`의 4프레임 보행 주기에 반복 횟수만 바꿔 등록했다.
  신규 모션의 완료 허용 오차는 기존 런타임 정책인 5°를 유지한다.
- `골넣기실전`은 `Downloads/robot_motions-1(1).json`의 동일 이름 모션만
  반영했다. 첫 두 프레임은 각각 600ms이며, 완료 허용 오차는 사용자 요청으로
  원본의 2° 대신 5°를 사용한다.

실물 실행 전 시뮬레이션에서 득점 경계값과 모션 완료 후 정지를 검증하고,
로봇을 지지한 상태에서 새 모션과 백보드 거리 기준을 확인해야 한다.

## Ball pickup 미세 접근

공 분석기의 최소 신뢰도는 0.30, 공 주행 판단기는 0.35다. YOLO 공 검출 기준 0.20과 검출 확정·깊이 유효성 조건은 유지한다.

미세전진·꽃게걸음·후진·제자리 회전은 완료 후 1초 동안 다음 모션을 보내지 않는다.
대기 중 관측은 사용하지 않고 종료 후 새 영상으로 재판단한다. 공 접근 최초 진입,
일반 전진과 이동형 RECOVER는 기존 흐름을 유지한다. `PICKUP_NOW`의 첫 정렬 판단은 즉시 시작한다.
픽업 고정 시퀀스의 모션 사이에는 1초를 두되, 공확인자세 관찰 시간은 기존 3초를 유지한다.
허들 연속 미세전진 사이와 마지막 미세전진에서 허들 넘기 전에도 1초를 둔다.

공이 마지막 검출 상자 기준 화면 내부에서 소실되면, 0.5초 이상·5개 이상 새 프레임의
소실 확인 후 `찐전진45(4회)`를 한 번 실행한다. 발행 후에는 재검출 전까지 반복하지 않는다.
화면 상단 10% / 좌우·하단 2% 경계에 걸린 경우와 위치를 모르는 경우에는 이 복구를 적용하지 않는다.
기존 화면 상단 소실 전진과 가까운 공 소실 후진 판단은 유지한다.

`공확인자세` 완료 후 3초 정지 구간에서 수신한 최신 최대 40개 프레임 중
`grab` confidence가 0.25 이상인 프레임이 15개 이상이면 `GRABBED`로 확정한다.
연속 검출일 필요는 없고, 마지막 프레임이 미검출이어도 이 횟수를 만족하면 성공이다.
한 프레임에 여러 `grab` 검출이 있어도 성공 1개로 세며, 중복·역순 타임스탬프와
확인 시작 전 이미 수신한 프레임은 집계하지 않는다. 40개보다 많이 수신하면 오래된 프레임부터
제외한다. 정지 구간에 40개 미만을 수신해도 최소 성공 횟수 15개는 그대로 적용한다.
3초 정지 종료 시 판정을 확정한 뒤 후진을 시작하며, 자세 동작 중과 후진 중 영상은
집계하지 않는다. 실물 적용 전 모의 실행과 로그로 수집 프레임 수를 확인한다.
새 프레임이 하나도 없으면 `UNKNOWN`, 프레임은 있지만 성공이 15개 미만이면
`NOT_GRABBED`다. 확인 종료 시 해당 공의 결과를 저장하며, 이후 영상으로 덮어쓰지 않는다.
`GRASP_VERIFY_END`와 판단 debug의 `decision_window_frames` 및
`decision_window_grabbed_frames`로 최종 판단에 사용한 프레임 수를 확인할 수 있다.
`accepted_frames`/`grabbed_frames`는 전체 확인 구간 통계이고,
`confidence`/`final_confidence`와 `last_fresh_frame_result`는 마지막 프레임 관측값이다.
이 기준은 일시적인 미검출에 더 관대하지만, 실제로 공을 놓친 경우에도 이전 성공
프레임이 15개 남아 있으면 성공으로 판정할 수 있다.

픽업 전 미세전진은 `미세0도-4`, 공 확인 후 후진은 `후진실전-2(2회)`이다.
550mm 이내 거리 판단으로 선택한 초기 접근 `찐미세45도-4`에는 준비 모션을 넣지 않는다.
이후 공잡기 전 미세 정렬 단계에서 `미세0도-4`를 요청할 때에는
`오뒤에서미세오뒤`를 먼저 1회 실행한다.
접근·보정 모션 완료 후 새 영상에서 미세 정렬이 확인되면
추가 준비 자세·미세전진 없이 `공잡기전후진-2(2회)`로 바로 진행한다.
정렬이 완료되기 전에는 기존 미세전진·꽃게걸음 보정과 완료 후 재판단을 유지한다.
초기/미세 정렬 중 마지막 유효 공 관측의 `bottom_distance_px`가 100px 이내였고
새 영상에서 공 유실이 아래의 0.5초·최소 5프레임 조건으로 확정되면,
회전 탐색 대신 `pickup_lost_ball_backward_1`을
한 번 실행한다. 현재 별칭은 `찐후진실전(1회)`를 가리키며 `repeat_count=1`이다.
이전에 보관하던 `후진실전-2(1회, 픽업 카메라0도)`는 카탈로그 36 정리에서 삭제했다.
후진은 미리 여러 번 예약하지 않으며, 1회 완료 → 새 영상 확인 후
계속 미검출일 때만 다음 1회를 실행한다. 공이 raw 검출만 되어도 추가 후진을
보류하고 확인을 기다린다. 이미 진행 중인 1회 후진은 균형 유지를 위해 완료한다.
영상이 없거나 오래되면 대기하며, 후진 실패·취소·시간 초과 시 시퀀스를 중단한다.
마지막으로 다시 관측한 공이 100px보다 멀면 이전 근접 기억으로 후진하지 않는다.
후진 완료 자체를 정렬 완료로 취급하지 않으므로, 공 재검출 후 기존 정렬을 거쳐
별도의 잡기 전 후진 2회를 정상 실행한다. 근접했던 공의 분실이 아니면 기존
탐색/대기 정책을 사용한다. 변경된 후진 복구는 모의 입력/시뮬레이션에서 먼저
확인하고, 실제 로봇은 지지 상태에서 카메라 시야와 전후 자세 연결을 검증한다.
브리지에는 `use_no_ball_pickup_path=true`용 별도 분기가 남아 있지만,
현재 판단 로직은 이 플래그를 생성하지 않는다. 이 분기는 준비 모션과 미세전진,
후진을 수행한 뒤 공 재검출·정렬 확인을 거쳐야 잡기로 진행한다.
준비 모션 성공 직후 미세전진을 시작하고, 미세전진 완료 후 1초 정지하고
새 영상 확인을 진행한다. 준비 모션 실패·시간 초과·취소 시에는 미세전진을
실행하지 않는다. 준비 모션의 마지막 자세는 원본의 `미세오뒤401(90도)`이므로
0도 미세전진으로 이어지는 관절·카메라 자세 변화는 지지 상태에서 확인해야 한다.
명령 ID `pickup_retreat_2`는 유지하며, 실제 실행 모션은 `찐후진실전(1회)`이고 `repeat_count`는 1이다.
이 후진 모션은 `Downloads/robot_motions(26).json`에서 가져오고 완료 허용 오차만 기존 5°로 유지했다.
프레임·속도·시작/종료 자세는 기존 2회 후진과 같고 반복 횟수만 줄었다. 이후 공별 퇴장 회전은 유지한다.
공 확인 후 카메라 45도 후진에만 적용하며, 잡기 전 후진·근접 공 유실 후진·골대 후진은 변경하지 않는다.
공잡기 전 후진 `pickup_pre_backward_camera_down`은 `Downloads/robot_motions(15).json`의
`공잡기전후진-2(2회)`로 연결하며, `공잡기리그랩까지 실전`도 해당 파일의 데이터로 갱신했다.
오른쪽 꽃게는 `Downloads/robot_motions(29).json`의 `찐미세오옆꽃게0-1(1회)`(공잡기),
`찐미세오옆꽃게90-1(1회)`(골대)을 사용한다. 마지막으로 완료한 실제 모션이
공잡기 미세전진 `pickup_fine_forward_0`이면 `찐미세오뒤에서오옆꽃게0도`를,
골대 미세전진 `goal_camera_90_fine_forward_1~4`이면 `찐미세오뒤에서 오옆꽃게90도`를
먼저 1회 실행하고, 성공 직후 오른쪽 꽃게를 실행한다. 대기·영상 판단은 실제 모션
이력을 바꾸지 않으며 연속 꽃게에는 준비 모션을 반복하지 않는다. 준비 실패·시간 초과·
취소 시 꽃게를 실행하지 않는다. 꽃게 2개와 전환 3개는 완료 허용 오차만 기존 5°로 적용했다.
왼쪽 꽃게는 기존 `찐미세왼옆꽃게0도-1`(공잡기), `찐미세왼옆꽃게90도-1`(골대)의
데이터를 유지한다. 둘 다 4프레임·1회 반복·속도 0.95이며, 공잡기·골대 모두
왼쪽 꽃게 앞에는 준비 모션을 넣지 않는다. 일반 전진·미세전진 뒤에도 바로 실행한다.
골대 일반 전진 뒤 오른쪽 꽃게는 `goal_forward_to_crab_right_90` →
`찐오뒤에서 오옆꽃게90도`를 먼저 1회 실행한다. 공의 일반 전진 뒤에는 바로 꽃게를 실행한다.
오른쪽 전환과 왼쪽 직접 연결은 시뮬레이션에서 먼저 확인하고, 실물은 지지 상태에서 검증한다.
가져온 모션은 원본 프레임·시간·속도·반복 수를 유지하고 완료 허용 오차만 5°로 적용했다.
런타임 전체 모션의 `completion.position_tolerance_deg`도 5°로 통일한다.
향후 JSON을 교체하거나 일부 모션만 수동으로 가져올 때도 원본 값과 무관하게
실행용 허용 오차는 예외 없이 5°로 유지한다. 보관용 원본 JSON은 변경하지 않는다.
라인 기본 전진은 `전진실험45도(6회)`, 일반 BALL 접근은 `전진실험45도(4회)`,
픽업 고정 시퀀스와 정지 대기 후 필요한 추가 라인 정렬을 완료하면 기본 라인 제어기로 10초간 주행한다.
골대 일반 전진은 거리표에 따라 `전진실험90도(4회)` 또는 `전진실험90도(6회)`다.
이 전진 모션들은 `Downloads/robot_motions(21).json`에서 가져왔으며 완료 허용 오차만
5°로 적용했다. 각 모션은 2회 전진 분량의 8프레임으로 구성되어 있으며,
4/6/8회 모션의 `repeat_count`는 각각 2/3/4, `playback_speed`는 원본의 1.15다.
득점 후 라인 복귀 전진도
`line_forward_6` 별칭을 공유하므로 `전진실험45도(6회)`를 사용한다.
기존 전진과 관절 궤적·시간 설정이 다르므로 실제 연속 주행 전에 지지 상태에서 확인한다.
후진이 끝나면 첫 번째 공은 `후진하고 제자리우회전(공)`, 두 번째 공은
`후진에서 제자리좌회전(공)`을 실행하고 1초 정지한 뒤 픽업 시퀀스를 완료한다.
두 복합 모션은 `Downloads/robot_motions(19).json`에서 가져왔으며,
각각 `pickup_first_backward_turn_right`, `pickup_second_backward_turn_left` 별칭으로
1회만 실행한다. 첫 번째는 내부 우회전을 7회에서 11회로, 두 번째는 내부 좌회전을
실제 원본 4회에서 7회로 늘렸다. 그림의 두 번째 좌회전 3회 표기와 원본은 다르다.
전체 `repeat_count=1`은 유지하고 마지막 회전 2프레임을 우측 4세트·좌측 3세트 추가했다.
기존 후진과 회전 프레임은 보존하며, 새 회전의 간격은 우측 311ms·좌측 339ms를 유지한다.
전체 `max_seq_ms`는 우측 4144ms·좌측 3089ms다. 별도의 회전 명령은 추가하지 않는다.
회전량이 늘어나므로 시뮬레이션에서 순서와 자세 연결을 확인한 뒤 실물 지지 상태에서 검증한다.
네 공·골대 복합 모션 모두 원본의 관절 각도·토크·프레임 시간·재생 속도를 유지하고
완료 허용 오차만 5°로 적용했다. 이후 `tools/upsert_motion_catalog.py`로 가져오는
모션과 기존 런타임 모션에도 5°를 적용한다. 이는 관절 도달 판정의 허용 오차이며
영상 기반 라인 방향 정렬의 각도 기준과는 별개다.

두 픽업 모두 고정 시퀀스(잡기·공확인·후진·첫 번째 우/두 번째 좌 퇴장 회전)를
끝낸 즉시 `POST_BALL_LINE_ALIGN`으로 들어간다.
이때 픽업 전 라인 형상을 폐기하고 새 영상으로 라인 재검출을 판단한다.
라인이 미검출되거나 새 라인 정보가 없으면 첫 번째 공은 `찐제자리우회전45도-1(5회)`, 두 번째 공은
`찐제자리좌회전45도-1(3회)`로 첫 탐색을 한다. 시작 방향은 공 순서로 정하고,
이후 같은 방향 최대 3번·반대 방향 최대 6번은 좌 1회 / 우 2회로 탐색한다.
중간에 보인 라인 방향만으로 탐색 단계를 초기화하지 않는다. 각 탐색 회전이 끝나면
1초 정지하고 대기 중 라인 영상을 폐기한 뒤 새 영상으로 재판단한다.
라인이 검출되고 선택한 heading·좌우 위치·품질이 유효하면 남은 방향 오차를
제자리 회전으로 완전히 맞추지 않고 바로 `LINE_TRACK_AFTER_PICKUP`으로
넘어가 Ball mode를 종료한다. 이미 유효한 라인이 보이면 탐색 회전은 생략한다.
라인 정보가 없거나 오래되면 위 단계별 한도 안에서 탐색한다. 검출된 라인의 형상·품질이
유효하지 않으면 대기한다. 입력 부재 시 탐색 예외는 이 단계에만 적용하며,
실행 중 모션 잠금·실패 차단·정지 대기는 유지한다.
그 이후에는 일반 주행과 동일하게 heading·좌우 위치·코너에 따라 전진,
`RECOVER_*`, `LEFT`·`RIGHT` 및 일반 `LINE_LOST_TURN_*` 탐색을 선택한다.
일반 직진 `STRAIGHT`는 `line_forward_6`/`찐전진45(6회)`를 사용한다.
새 공이나 골대 검출은 이 10초 주행을 끊지 않는다.
10초는 첫 라인 모션의 `RUNNING` 수신부터 센 경과 시간이며 보정과 영상 대기도 포함한다.
시간이 지나면 현재 모션을 정상 종료한 뒤 잡기 결과로 분기한다.
이 시간 경계를 확인할 수 있도록 다음 직진을 미리 예약하지 않는다.
라인 모션이 실패·취소·시간 초과되면 추가 주행과 카메라 전환을 중단한다.

10초 후 해당 공의 저장된 잡기 결과가 `GRABBED`이면 `POST_BALL_GOAL_TRANSITION`에서
`오뒤카메라90도`를 실행한다. 추가 3초 정지 없이 카메라 모션 성공까지 기다린다.
이후 기존 골대 영상을
폐기하고 새 영상으로 `GOAL_APPROACH`를 시작한다. 추가 라인 재정렬이나
별도의 3초 정지는 넣지 않는다. 카메라 모션 실패·시간 초과 시에는 접근하지 않는다.
잡기 결과가 `NOT_GRABBED` 또는 `UNKNOWN`이면 카메라를 들지 않고 라인 주행을
이어간다. 이 공 구간은 `ball_sections_processed`에만 통과 처리하며
`shots_completed`는 올리지 않는다. `AUTO`에서 다음 공을 찾을 수 있고,
모든 공 구간을 통과했다면 `LINE_TRACK`을 유지한다. 다음 픽업 전에는 골대
검출이 주행을 가로채지 못한다. 다음 슛은 건너뛴 공이 아닌 해당 공의 잡기 결과를 쓴다.
`mission_progress.ball_mode_active`는 공 접근·픽업 시퀀스·픽업 후 라인 정렬까지만
`true`다. 라인 정렬 완료 이후에는 `false`다. 후진·제자리 회전은 픽업 시퀀스
내부이며, 10초 일반 라인 주행은 픽업 시퀀스 이후 단계다.
`pickups_completed`는 잡기 시퀀스 완료 횟수이므로 ball mode 종료와 별도로 유지한다.
카메라 전환 실행 중에는 같은 전환 명령을 다시 발행하지 않는다.

픽업 완료부터 10초 라인 주행과, 잡기 성공 시 골대 접근·슛 후 라인 복귀까지는
새 공 검출로 공 접근이나 탐색을 시작하지 않는다. 단계 전환 시 남은 공 접근·잡기
예약, 검출 확정 대기, 마지막 공 위치·탐색 방향과 공 접근용 정지 시간을 정리한다.
실행 중인 모션의 잠금, 라인·골대의 정지 시간, 잡기 판정 결과와 완료 횟수는 유지한다.
슛 후 복귀 전진이 성공하면 이전 공·골대 영상을 폐기하고 완료한 골대의 제어 잠금과
추적도 정리한다. `AUTO`로 복귀한 뒤 새 영상에서 다음 공 탐색을 재개한다.
잡기 전 공을 놓쳤을 때의 기존 탐색은 그대로 유지한다.

픽업 중 일반 전진 완료 후에는 별도 준비 자세 없이 요청한 꽃게걸음을 실행한다.
초기 접근의 미세45도 또는 후속 미세0도 완료 후 오른쪽 꽃게는 위의
`찐미세오뒤에서오옆꽃게0도`를 거친다.
꽃게걸음 완료 후 1초 정지하고 새 영상 정렬 판단으로 돌아가며,
연속 꽃게걸음에서는 준비 자세를 반복하지 않는다.
전진·미세전진 종료 자세에서 꽃게걸음으로 연결되는 구간은 시뮬레이션에서 먼저 검증한다.

BALL과 HURDLE의 기본 거리별 접근은 550 mm 초과이면 `STRAIGHT` →
`찐전진45(4회)`, 이하이면 `STRAIGHT_0` → `찐미세45도-4`를 사용한다.
BALL은 `distance_m`, HURDLE은 `depth_m`으로 선택하며 정렬·잡기·넘기 조건이
먼저 적용된다. 일반 Line의 `STRAIGHT` 매핑은 기존 6회 전진을 유지한다.
BALL은 550 mm 이하에서 pickup 시퀀스에 진입하며, 내부 초기 정렬 후의
거리별 접근에도 같은 550 mm 기준과 카메라 45도 모션을 적용한다.

일반 BALL 접근의 `550 < distance_m <= 1500 mm`에서는 제자리 정렬을 하지 않는다.
유효한 공 지면 방향각 `ground_steering_angle_deg`가 -15° 이하이면
`BALL_APPROACH_RECOVER_LEFT_4` → `찐라인복귀좌회전45도(4회)`,
+15° 이상이면 `BALL_APPROACH_RECOVER_RIGHT_4` → `찐라인복귀우회전45 도(4회)`,
그 사이이면 기존 전진 4회를 선택한다. 라인 관측은 선택에 사용하지 않는다.
recover는 약 30°의 이동형 보정이며 한 번 완료할 때마다 새 공 관측으로 재선택한다.
회전각이 작아지면 전진, 기존 거리값이 550 mm 이하이면 픽업으로 전환한다.
관측이 유효하지 않으면 새로운 recover를 시작하지 않는다. 보정 진입 기준은 15°이며,
고정 보정량은 유지되므로 반대 방향 과보정과 반복 보정 여부를 확인한다.
특히 550 mm 부근의 전진량·옆 이동량·잔여 각도는 시뮬레이션과 지지 상태에서 검증한다.

공 접근 중 정지 시간을 줄이기 위해 이동 중에도 공 방향 정렬 판단을 준비한다.
최초 공 진입은 최근 30프레임 중 위치·크기가 일관된 공을 12회 검출하면 확정한다. 미확정 후보의 유효한 거리가
`slowdown_depth_m`(기본 1.0 m)보다 멀고 depth age가 0.2초 이내이면
후보만을 이유로 라인 주행을 보류하지 않는다. 1.0 m 이하이거나 거리/깊이 신선도를
확인할 수 없으면 기존 경계 대기를 유지한다. 후보가 보이는 동안에는 다음 라인
전진을 미리 큐에 넣지 않고, 현재 동작 종료 시 공 진입 여부를 다시 판단한다.

이미 공 접근을 시작한 경우에만 짧은 재확인을 허용한다. 최근 0.5초 이내에 확정한
공과 비교하여 화면 크기가 같고, 정규화 중심 이동 0.05 이하, 면적 비율 0.7 이상,
거리 차이 0.15 m 이하인 서로 다른 연속 RGB 프레임 3개를 사용한다.
각 후보의 depth age는 0.2초 이내여야 하며, 550 mm 초과의 접근 구간과
화면 하단 거리 120px 초과에서만 적용한다. 후보가 다른 물체로 바뀌거나
확정 기준 관측이 만료되면 빠른 재확인을 허용하지 않는다. 이 값들은 초기 검증값이며,
빠른 재확인 결과만으로 최초 공 진입이나 픽업을 허용하지 않는다.
분석기의 원래 `detected` 값은 그대로 유지하고 판단 노드 내부의 접근 관측에만 적용한다.

공 관측이 준비되면 다음 10 Hz 타이머까지 기다리지 않고 기존 안전·모션 잠금을
거쳐 판단한다. 일반 접근 완료 후에는 완료 시각보다 뒤에 촬영된 RGB가 필요하며,
지연된 이전 프레임·역순·중복 프레임으로 다음 접근을 시작하지 않는다.
제자리 회전 뒤 `BALL_POST_MOTION_DWELL_SEC = 1.0`은 유지하고, 이 대기가
끝난 뒤 촬영된 새 공 프레임을 요구한다. 대기 만료만으로 전진을 허용하지 않는다.
`BALL motion boundary: wait_sec=..., next_action=..., reobserved=...` 로그로
동작 완료부터 다음 명령까지의 시간을 확인할 수 있다. 해당 시간에는 필요한 안정화와
관측 지연도 포함된다. 변경 후 먼저 모의 입력/시뮬레이션으로 확인하고,
실기에서는 가까운 공을 지나치거나 오검출을 따라가지 않는지 지지 상태에서 검증한다.

픽업 초기·후진 후 제자리 회전은 기존 정렬 필요 조건에 더해
`depth_valid=true`, 신선한 `0 < depth_m <= 0.550`,
`bottom_distance_px > 120`을 모두 만족할 때만 허용한다.
기존 `distance_m` 접근·픽업 진입 정책과 `depth_m` 회전 허용 조건은 구분한다.
120px 이하에서는 회전하지 않으며 초기 좌우 오차는 꽃게걸음으로 보정한다.
관절 완료 허용 오차 5°와 픽업 고정 시퀀스는 변경하지 않는다.

- `pickup_fine_step_distance_m` 기본값 `0.550`: 550 mm 초과이면
  `STRAIGHT` → `찐전진45(4회)`, 이하이면 `STRAIGHT_0` → `찐미세45도-4`다.
  거리값이 없거나 0 이하, `depth_valid=false`, `depth_age_sec`가 없거나
  0~0.70초 범위를 벗어나면 전진을 대기한다.
- `pickup_fine_align_bottom_distance_px` 기본값 `140`: 미세실전 완료 후
  새 영상의 `bottom_distance_px`가 이 기준보다 크면 미세실전을 반복한다.
  이하이면 꽃게걸음으로
  좌우 정렬하고, `offset_x_px`가 `-30~+55` 범위에 들어오면 추가 미세전진 없이
  공잡기 전 후진 단계로 넘어간다.

매 동작 후 새 영상 확인을 거치며, 회전 후에만 3초 대기한다. 픽셀 간격이 유효하지
않으면 대기한다. `bottom_distance_px`는 화면 하단과 공 중심 사이 픽셀 간격이며,
근접 게걸음 및 미세전진 이후 정렬에 계속 사용한다. 두 기준은 독립적이며
두 full-system launch에서 인자로 조정할 수 있다. 기존
`pickup_fine_step_bottom_distance_px` 인자는 미터 단위의
`pickup_fine_step_distance_m`으로 교체했다. 픽셀 기준은 카메라 각도와 해상도에 영향을
받으므로 반복 접근은 먼저 모의 입력으로 확인하고 실물 이동량을 검증해야 한다.

공 유실은 `motion_decision_node`에서 **연속 미검출 0.5초 이상과 새로운 미검출
프레임 최소 5개를 모두 만족**해야 확정한다. `detected` 또는 `raw_detected`가
참이면 즉시 누적을 초기화한다. `rgb_stamp_ns`가 증가한 프레임만 세며, 중복·역순
프레임은 최신 입력 수신 시각도 갱신하지 않는다. 타임스탬프 없는 미검출은 세지
않는다. 입력 수신 간격이나 영상 타임스탬프 간격이 `ball_timeout_sec`(기본 0.5초)를
넘으면 연속성을 다시 확인한다. 지연된 프레임 묶음으로 유실을 확정하지 않도록
영상 시각과 수신 시각 양쪽에서 0.5초를 확인한다.
확정 전에는 새 접근·탐색·유실 복구 후진을 대기하고, 실행 중인 모션은 유지한다.
일반 접근, 픽업 정렬 중 유실 기록, `BALL LOST` 디버그 상태가 같은 확정 결과를
사용한다. 화면과 판단 메시지 사이의 타임스탬프 동기화 방식은 변경하지 않는다.
잡기 전 필수 후진, 고정 잡기 시퀀스, grab 40/15 판정은 이 조건과 별개다.

`enable_ball_lost_recovery` 기본값은 `true`다. 유효한 거리로 1.5m 이내에서
확인한 공의 마지막 화면 좌우 방향을 기억하고, 새 영상으로 유실이 확정되면
그 방향으로 제자리 탐색 회전을 실행한다. 화면 가장자리를 실제로 통과해야 하는
조건은 없다. 화면 내부 유실 전진과 상단 이탈 전진, 픽업의 근접 유실 후진을
우선 유지하며, 해당 복구 분기가 없으면 회전한다. 근접 유실 후진 조건이 유지되는
동안에는 후진 완료 후 새 영상으로 재판단하며 회전으로 전환하지 않는다.
일반 접근의 첫 탐색은 `찐제자리좌회전45도-1(3회)` / `찐제자리우회전45도-1(5회)`,
픽업 초기·미세 정렬에서는 같은 횟수의 카메라 0도 모션을 사용한다.
모션명의 45도/0도는 카메라 자세이며, 첫 탐색의 보정된 몸체 회전량은 좌우 모두 45도다.
이후 좌 1회 / 우 2회(15도씩)로 같은 방향 최대 3번, 반대 방향 최대 6번 탐색한다.
완료 후 1초 대기와 새 영상 확인을 거쳐 재판단하고 픽업에서는 같은 정렬 체크포인트로
돌아온다. 한 번의 유실에서 첫 방향 90도·반대 방향 90도 한도를 공유한다.
방향 기억이 없거나 영상이
오래됐거나 유실 미확정이면 회전하지 않는다. 화면은 실제 선택 명령에 따라
`BALL LOST | SEARCH LEFT/RIGHT`, `WAIT`, `SEARCH LIMIT`를 구분한다.
잡기 전 공의 `bottom_distance_px`가 100px 이하로 한 번 확인되면 해당 픽업은
기존 근접 정렬 상태를 유지한다. 이후 픽셀값이 커져도 제자리 회전 대신
미세전진·꽃게걸음을 사용한다. 새 픽업 시작과 종료 시 이 상태를 초기화하며,
잡기 후 고정 퇴장 회전과 라인 복귀 회전에는 적용하지 않는다.
마지막 공 검출 상자의 위쪽 끝이 화면 상단 10% 이내에 있고 이후
`detected=false`, `raw_detected=false`가 되면 좌우 탐색보다
`전진0도-1(2회)`를 우선 실행한다. 720px 높이에서는 상단 72px까지이며,
`MotionDecisionPlanner.BALL_LOST_TOP_EDGE_RATIO`에서 기준을 조정한다.
이 조건은 상단 이탈의 영상 기반 추정이며, 일반 접근과 픽업 초기·미세 정렬에
적용한다. 높이/검출 상자가 없거나 유효하지 않으면 상단 이탈로 판단하지 않는다.
한 번의 공 분실에 전진 모션은 한 번만 실행하고, 완료 후 새 영상에서도
계속 LOST이면 위 우선순위와 제한에 따라 마지막 화면 방향으로 탐색한다.
신뢰도 기준을 만족하는 공을 다시
관측하면 새 위치로 판단을 갱신한다. 잡기 고정 시퀀스가 시작된 뒤에는 적용하지
않는다. 새 전진 분기는 모의 입력/시뮬레이션에서 먼저 검증해야 한다.

진행 중인 모션을 중단하지 않으며, 새 프레임이 없거나 raw 검출의 확정을
기다리는 동안에는 새 탐색 회전을 시작하지 않는다. 실제 잡기 순서가 시작된
후에는 이 탐색을 적용하지 않는다. YOLO 상단에는 분실 중 `BALL LOST`와
마지막 탐색 방향을 표시하며, 모터 오류 표시는 그보다 우선한다.

픽업 초기 정렬·후진 후 재정렬은 Path angle(`steering_angle_deg`)을
우선 사용한다. 일반 공 접근은 위의 지면 방향각 기반 이동형 recover 정책을 사용한다.
라인 재정렬은 heading, 골대 정렬은 bearing을 사용하며,
허용된 픽업 제자리 정렬·라인·골대 정렬은 다음 공통 표를 사용한다. 각 구간의 시작 각도는 포함하며,
정확히 15°는 1회, 30°는 2회, 45°는 3회, 90°는 6회다.

| 좌측 각도 오차 | 좌회전 횟수 | 우측 각도 오차 | 우회전 횟수 |
| --- | --- | --- | --- |
| 15° 미만 | 회전 없음 | 15° 미만 | 회전 없음 |
| 15° 이상 ~ 30° 미만 | 1회 | 15° 이상 ~ 30° 미만 | 2회 |
| 30° 이상 ~ 45° 미만 | 2회 | 30° 이상 ~ 45° 미만 | 3회 |
| 45° 이상 ~ 60° 미만 | 3회 | 45° 이상 ~ 65° 미만 | 5회 |
| 60° 이상 ~ 75° 미만 | 4회 | 65° 이상 ~ 95° 미만 | 7회 |
| 75° 이상 ~ 90° 미만 | 5회 | 95° 이상 | 9회 |
| 90° 이상 | 6회 | — | — |

라인 재정렬은 카메라45도용, 픽업 정렬은 카메라0도용,
골대 정렬은 카메라90도용 모션에 연결한다. 좌회전 1~6회 모션 18개는 최신
`Downloads/robot_motions(29).json`과 일치한다. 관절 각도·속도·프레임·반복 수는
원본을 유지하고 완료 허용 오차만 기존 실행 정책인 5°를 적용한다.
좌회전 1~6회의 매핑 각도는 15°·30°·45°·60°·75°·90°이며, 우회전
2·3·5·7·9회는 15°·30°·45°·65°·95°다. 양쪽 모두 `turn_repeat_deg`는
`null`이고 `turn_angle_deg`는 해당 매핑 각도다. 실제 회전량은 모의 입력 검증 후
실물 지지 상태에서 확인해야 한다. 이전보다 작은 오차부터 좌회전하며 같은 오차에서
선택 횟수가 늘어나므로, 먼저 시뮬레이션에서 회전 후 잔여 오차와 과회전을 확인한다.
목표 미검출 시 탐색과 픽업·슛 이후의 고정 회전에는 이 각도별 선택을 적용하지 않는다.
공 초기 정렬에서 픽셀 오차가 ±70px를 넘으면 픽셀 부호로 방향을 선택한다.
가까운 공의 게걸음 정렬과 Path angle의 근거리 중앙 deadband는 유지한다.
골대 득점 거리에서의 게걸음 정렬도 유지한다. 각도 기준 아래에서는 제자리
회전을 건너뛰므로 기존보다 큰 잔여 오차 상태로 다음 전진/정렬 단계에 진입할 수 있다.

공 분실 시 새 영상의 유실 확정 후 마지막 화면 방향으로 제한된 탐색 회전을 한다.
잡기 후 고정 퇴장 복합 모션은
기존 첫 공 우11회·둘째 공 좌7회를 유지한다.
일반 라인 `RIGHT`는 `line_turn_right_large` → `제자리우회전45도(9회)`로 연결한다.
`line_turn_right_2/3/5/7/9`도 각각 같은 횟수의 카메라45도 제자리우회전으로 연결한다.
관절 프레임은 변경하지 않았다.
`full_system_robot.launch.py`의 초기 자세는 `오뒤412`이고 전환 시간은 기존 4초다.
변경된 회전량과 분실 탐색은 모의 입력 및 지지대 실험 후 자유 보행에 적용한다.
현재 모션 데이터는 `robot_motions(12).json` 원본과 동일하다.
45도 자세의 9회 우회전만 원본 이름이 `제자리우회전45도(9회)`이며 `-1`이 없다.

위 deprecated executable을 하나도 실행하지 않는다.

## 카메라 좌우 영역

라인 분석의 좌우 ROI 기본값은 `0.0~1.0`으로 전체 폭을 사용한다.

## 라인 복귀 매핑과 소실 탐색 (2026-09-26)

`RECOVER_<라인 위치>_TURN_<회전 방향>_4`에서 앞쪽 LEFT/RIGHT는 라인 위치이고,
실행 모션은 뒤쪽 TURN 방향으로 고른다. 기존 RECOVER 진입·해제 조건과 회전 방향
판단은 유지하며, 한 번에 실행하는 반복 횟수만 4회로 고정한다.

| 명령 | 실행 모션 | 예상 회전량 |
| --- | --- | --- |
| `RECOVER_LEFT_TURN_LEFT_4`, `RECOVER_RIGHT_TURN_LEFT_4` | `찐라인복귀좌회전45도(4회)` | 약 30° |
| `RECOVER_RIGHT_TURN_RIGHT_4`, `RECOVER_LEFT_TURN_RIGHT_4` | `찐라인복귀우회전45 도(4회)` | 약 20° |
| `LINE_LOST_TURN_LEFT_3` / `_LEFT_1` | `찐제자리좌회전45도-1(3회)` / `(1회)` | 첫 탐색 45° / 추가·반대 탐색 15° |
| `LINE_LOST_TURN_RIGHT_5` / `_RIGHT_2` | `찐제자리우회전45도-1(5회)` / `(2회)` | 첫 탐색 45° / 추가·반대 탐색 15° |

브리지는 위 네 RECOVER 명령만 실행한다. 6회 등 다른 RECOVER 횟수 요청은 거부한다.
JSON의 `찐라인복귀좌회전45도(6회)` 데이터와 별칭은 보관하지만 자동 주행에서는 사용하지 않는다.
우회전 4회 모션은 `robot_motions(32).json`의 `찐라인복귀우회전45 도(4회)`로 교체했다.
이름의 공백을 포함해 원본 관절 각도·토크 플래그·프레임 시간·속도·반복 수·종료 자세를
유지하며, 완료 허용 오차만 런타임 정책인 5°로 적용한다.
같은 별칭을 쓰는 일반 `RIGHT`와 `BALL_APPROACH_RECOVER_RIGHT_4`에도 적용된다.
원본 모션은 `artifacts/catalog32_right_recovery_source.json`에 보관한다.
좌회전과 다른 모션 데이터는 이번 교체에서 변경하지 않았다.
30°/20°는 사용자가 지정한 예상 회전량이며 실제 회전량은 바닥과 자세에 따라 달라질 수 있다.

RECOVER에는 고정 정지 시간을 넣지 않는다. 유효한 새 판단이 나오면 4회를 실행하며,
실행 중에는 다음 주행을 미리 예약하지 않는다. 정상 완료 뒤 이전 라인 관측을 폐기하고,
새 영상에서 여전히 RECOVER 조건이면 추가 정지 대기 없이 다시 4회를 실행한다.
영상 갱신과 모션 성공 확인을 기다리는 조건은 유지한다.
성공 후 재판단을 반복하는 횟수에는 별도 제한을 두지 않는다. 정상 라인 주행 조건이면
RECOVER를 종료하고, 영상이 오래됐거나 품질이 부족하면 대기한다.
실패·거부·시간 초과에 대해서는 기존 모션 게이트와 안전 정지 처리를 유지한다.
기존보다 작은/큰 한 단위의 회전으로 바뀔 수 있으므로 실기 전에 모의 입력으로 확인하고,
지지 상태에서 4회 모션의 실제 회전량과 반복 시 과보정을 확인한다.

라인 제자리 회전인 `LEFT`·`RIGHT`, `LINE_LOST_TURN_*`,
`POST_BALL_LINE_TURN_*`, 호환용 `POST_SHOT_LINE_TURN_*`는 실행 전 3초 정지한다.
정지 시간은 이전 모션이 끝나고 해당 판단이 시작된 뒤부터 세며 모션 실행 중 시간은 포함하지 않는다.
회전 판단이 바뀌면 대기를 초기화하고, 전진/RECOVER로 바뀌면 회전 대기를 취소한다.
픽업 추가 정렬의 기존 회전 후 3초 정지는 별도로 유지한다.
고정 골대 퇴장 회전은 기존 `POST_SHOT_TURN`의 실행 전 3초 정지를 그대로 사용한다.

### 골넣기 완료 후 라인 복귀

`SHOT`의 정상 완료 상태를 받은 뒤 다음 순서로 실행한다.

1. `POST_SHOT_TURN`: 3초 정지 후 첫 번째 골대는 `찐기본자세에서 제자리 우회전(골대)`,
   두 번째 골대는 `찐기본자세에서 제자리좌회전(골대)`를 각각 1회 실행한다.
2. 고정 퇴장 회전 성공 시 바로 `LINE_TRACK`으로 전환한다. 회전 뒤 3초 정지하고
   정지 중 관측을 폐기한 뒤 새 영상으로 일반 라인 주행 판단을 실행한다.
   골대 잠금과 골대·공의 이전 관측, 이전 라인 탐색 방향은 지운다.
   이때 새 라인 결과가 미검출이면 퇴장 방향을 유지하여 첫 번째 골대는
   `찐제자리우회전45도-1(5회)`, 두 번째 골대는 `찐제자리좌회전45도-1(3회)`로
   첫 탐색을 한다. 이후 아래 단계별 한도에 따라 좌 1회 / 우 2회를 사용한다.
   탐색 회전 전후 1초 정지하고, 완료 후 대기 중 관측도 폐기한 다음 새 라인 결과를
   확인한다. 실행 잠금은 유지한다.
   라인이 검출되면 이 탐색을 해제하고 즉시 기존 일반 라인 판단에 맡긴다.
   퇴장 직후부터 라인이 보이면 탐색하지 않으며, 이후 다시 라인을 잃어도 일반
   라인 유실 처리를 따른다. 입력이 없거나 오래됐으면 대기하고, 탐색 모션이
   실패·취소·시간 초과되면 재실행하지 않고 정지한다.
   `POST_SHOT_LINE_ALIGN`과 `POST_SHOT_FORWARD`를 자동 진입하지 않는다.
3. 일반 라인 제어가 heading·좌우 위치·코너에 따라 전진, RECOVER 또는 회전을 선택한다.
   별도의 heading 전용 회전과 강제 전진은 추가하지 않는다.
   같은 라인 입력이면 일반 주행과 같은 판단을 사용한다.

고정 퇴장 회전 실패·취소·시간 초과 시에는 해당 단계에서 정지하며 재실행하지 않는다.
허들 `GO` 성공도 이전 접근 phase로 복귀하지 않고 `LINE_TRACK`으로 전환한다.
허들 잠금을 해제하고 새 라인 관측을 요구하며, 같은 허들은 화면에서 사라질 때까지
재진입하지 않는다. 실패 시 기존 `HURDLE_APPROACH` 처리와 재시도 제한을 유지한다.
`LINE_TRACK` 중 새 ball·goal·hurdle의 진입 조건이 충족되면 기존 미션 우선순위를 따른다.
`POST_SHOT_LINE_ALIGN`과 `POST_SHOT_FORWARD`는 외부 수동 입력 호환용으로만 남긴다.
공 잡기 이후의 `POST_BALL_LINE_ALIGN`은 필요한 추가 제자리 정렬을 위해 유지한다.

골대 복합 모션은 `Downloads/robot_motions(19).json`의 원본 데이터를 기반으로,
마지막 회전 세트를 기존 시간 간격으로 각각 2세트씩 추가했다.
내부 회전은 첫 번째 우회전 9회, 두 번째 좌회전 6회이며, 자세 전환도 포함되어 있다.
기존 액션 ID `POST_SHOT_TURN_RIGHT_9` / `POST_SHOT_TURN_LEFT_4`는 호환성을 위해
유지하지만 실제 실행은 `post_shot_default_turn_right` / `post_shot_default_turn_left`
별칭으로 위 복합 모션을 호출한다.
실기 적용 전 시뮬레이션에서 골넣기 종료 자세와 회전 시작 자세의 연결을 확인하고,
지지 상태에서 회전량과 전진을 검증해야 한다.

일반 라인 주행(AUTO, LINE_TRACK 및 공/골대 탐색 중 라인 주행)에서 정상 검출한
가장 가까운 라인 점의 좌우 방향을 기억한다. 보행 중 수신한 영상도 갱신에 사용하며,
원시 검출점 좌표가 없는 입력은 lateral offset으로 판단한다. 라인을 새 영상에서
미검출하면 기억한 방향의 제자리 회전을 한 번 실행한다. 회전이 완료되어야 다음
명령을 허용하고, 회전 중 받은 라인 정보는 폐기한 뒤 새 영상으로 재판단한다.
다시 보이면 정상 주행으로 복귀하고, 여전히 미검출이면 같은 절차로 탐색한다.

일반 라인 주행과 공 처리 후 라인 재진입은 위 `line_heading_source` 설정을 따른다.
기본 지면각 모드는 0.35~1.05m 보정 범위와 최소 유효점 3개 조건을 유지하며,
지면 피팅이 무효이면 정지·대기한다. 선택 가능한 화면각 모드는 지면 피팅 무효만으로 멈추지 않는다. 양 모드에서 offset과
preview는 영상 기준이며, 같은 녹화로 방향·명령 차이를 비교한 뒤 실물에 적용한다.

기본 라인 미검출 조건은 다음과 같다. 검출·소실 임계값은 이번 전환 변경에서 수정하지 않았다.

- YOLO `line` 신뢰도 0.40 이상, ROI와 bbox 조건을 통과한 점을 중복·연속성 필터링한다.
  유효 점이 2개 미만이거나 전체 경로 피팅에 실패하면 `raw_detected=false`이다.
- 첫 검출/추적 기록 초기화 후 최근 3프레임 중 2프레임에서 검출되어야 확정한다.
  현재 프레임이 미검출이면 곧바로 `detected=false`이다.
  `confirmation_max_missed_frames=2`는 3연속 미검출 때 추적 기록을 초기화하는 기준이며,
  소실 탐색 실행을 3프레임 지연시키는 조건이 아니다.
- 새 `detected=false` 영상과 기억한 라인 방향이 있으면 제자리 탐색이 후보가 된다.
  발행 시 첫 탐색은 `LINE_LOST_TURN_LEFT_3`(좌 3회) 또는 `_RIGHT_5`(우 5회),
  이후는 아래 단계별 유실 탐색 한도를 따른다. 별도의 소실 지속시간 조건은 없다.
  모션 실행 중에는 완료를 기다리고, 소실 회전 이후에는 새 영상을 받아 재판단한다.
- 라인 관측이 0.5초보다 오래되면 플래너 입력에서 제외하여 대기한다.
  검출은 되어 있으나 유효한 품질 값의 최솟값이 0.35 미만이면 `low_line_quality`로
  정지한다. 이는 `LINE_LOST_TURN_*` 탐색 조건과 구분된다.

관측 누락·시간 초과·기억한 방향 없음은 정지한다. 공/골대/허들 단계가 선택되면
일반 라인 방향 기억을 지우며 해당 미션의 우선순위를 유지한다. 공 잡기 후 추가 정렬이 끝난 뒤와 골·허들 종료 후에는
동일한 일반 라인 소실 판단을 사용한다. 라인이 사라졌을 때는
이전 라인 형상으로 준비한 RECOVER 명령보다 소실 탐색을 우선하며, 오래된 검출
프레임만으로 다음 STRAIGHT를 미리 예약하지 않는다.

재매핑으로 실제 보행 주기와 반복 수가 달라졌으므로, 기존 각도 추정값과 실제
회전량이 일치하는지는 시뮬레이션 후 지지 상태에서 확인해야 한다. 특히 오른쪽
소실 탐색은 `찐제자리우회전45도-1(5회)`이며 종료 자세가 `오뒤415`이다.

## YOLO 실행 모션 표시

YOLO 상단 배너는 `/motion/status`의 `RUNNING` 상태를 받아 실제 실행 모션을 표시한다.
판단 명령이 `PICKUP_NOW` 하나여도 준비 자세·미세전진·꽃게·후진·잡기·공 확인·회전을
각각 구분한다. 라인 복귀, 제자리 회전, 골대 후진과 미세전진도 표시하며,
OpenCV 기본 글꼴에서 읽을 수 있도록 영문 모션 이름을 사용한다.
실행 표시를 판단 배너 위에 그리되 기존 오류·공 분실·잡기 확인 표시는 우선 유지한다.
관련 명령 종료 시 실행 표시를 지우고, 종료 메시지가 누락돼도 120초 뒤에는 만료한다.

픽업 전진의 `ball_camera_down_forward_2/4`는 기존 ID를 유지하지만 각각
`찐전진45(2회/4회)`로 연결한다. 두 모션 모두 카탈로그 30 데이터를 사용하며
카메라를 내리지 않는다. 2회 탐색은 동일한 8프레임을 repeat_count=1로 사용한다.
이 전진이 실행 승인되면 이전 공 접근의 카메라 하향 override를 해제하여
모션 원래의 카메라45 각도를 따르게 한다.

픽업이 거절·실패·시간 초과로 끝나면 새 공 관측으로 재시도를 허용하며,
거절도 픽업 실패 횟수 제한에 포함한다. 성공한 픽업의 중복 방지는 유지한다.
골대가 정렬 범위 안에서 득점 확정만 기다릴 때는 이미 시작한 슛 전 3초
정지 시간을 유지한다. 범위 이탈·검출 상실·무효 깊이이면 정지를 다시 시작하며,
최종 SHOT은 최신 득점 확정과 공 보유 확인을 모두 통과해야 한다.

허들 통합 제어는 확정 검출과 유효한 Depth Z를 사용한다. **700 mm 초과부터 1 m까지**는
라인 중심점들을 허들 박스 하단까지 연장해 얻은 교차점을 목표로 삼는다. 교차점과 보정된 로봇
중심의 x 차이가 영상 반폭의 10%를 넘으면, 왼쪽은 `RECOVER_LEFT_TURN_LEFT_4`, 오른쪽은
`RECOVER_RIGHT_TURN_RIGHT_4`를 요청한다. 각각 기존 `line_recovery_left_4`와
`line_recovery_right_4` 모션을 사용하며 제자리회전 횟수를 계산하지 않는다.
허용 범위 안에서는 `STRAIGHT` → `찐찐전진45(4회)`로 접근한다.
교차점을 구할 수 없거나 연장선이 허들 폭을 벗어나면 대기한다. 회전 전의 교차점을 보관해
다음 회전에 재사용하지 않는다. 허들 박스 중심각과 평행각은 이 제어의 회전 조건이 아니다.

유효한 `0 < Depth ≤ 700 mm`가 관측되면 미세 접근 진입을 예약한다. 실행 중인 라인/허들
동작을 완료한 뒤 `HURDLE_POSITIONING`으로 진입한다. 진입 이후에는 거리값이 다시 700 mm를
넘어도 회전을 재개하지 않으며 `찐미세0도-4`로 접근한다. 이 진입 자체는 GO를 예약하지 않는다.
각 접근 완료 후 새 허들 관측으로 거리를 판단하며, 미세 구간에서는 라인 교차점이 없어도 된다.

**유효한 Depth Z가 540 mm 이하**이면 `GO`를 요청한다. 마지막 GO는 다음 묶음을 실행하며,
앞서 접근 중 실행한 미세 전진은 이 두 번에 포함하지 않는다:

`찐미세0도-4` → **1초 정지** → `찐미세0도-4` → **1초 정지** → `찐허들`

각 미세 전진은 저장된 모션 전체를 한 번 실행하며 내부 `repeat_count`는 바꾸지 않는다.
이 마지막 묶음 안에서는 다른 미션이나 영상 재판단이 끼어들지 않는다. 실패·취소·거절·시간
초과 시 다음 단계로 진행하지 않으며, 재시도에는 이미 성공 완료한 단계가 중복되지 않는다.
두 번째 미세 전진은 별도 request ID를 사용해 이전 완료 메시지와 구분한다.
평행 ±8°·분석기 GO 확정 조건은 추가하지 않는다.

카메라 내리기(`Bottom dy ≤ 120 px`)와 근접 회전 금지(`≤ 100 px`)는 유지한다.
`bottom_distance_px`는 `영상 높이 - 1 - 허들 중심 y`이며 0 미만은 0이다.
미세 진입 전이라도 근접 회전 금지에 걸린 상태에서 교차점 보정이 필요하면 대기한다.
회전 금지와 미세 진입 상태는 해당 허들 미션이 끝날 때 해제한다. 마지막 묶음 시작 전에
검출 또는 깊이가 사라지면 대기한다. 이미 확정해 예약한 마지막 묶음의 유지 정책은 동일하다.
550 mm 또는 700 mm 진입만으로 마지막 묶음을 시작하지 않는다.

복귀 모션은 전진 성분을 포함하므로 700 mm를 통과하는 도중에도 시작한 모션은 끝까지
실행된다. 새 정책은 먼저 시뮬레이션에서 좌우 모션의 이동량과 경계 통과를 확인해야 한다.

`hurdle`은 `robot_motions(37).json`의 `찐허들`에 연결한다.
원본은 `artifacts/20260929_catalog37_hurdle_update/source_hurdle.json`에 보관하며 관절값·속도·반복 횟수는
그대로 사용하고 실행용 완료 허용 오차만 5°로 통일한다. 허들 모션의 `SUCCEEDED` 후에만 완료 횟수를
올리고 허들 잠금·근접 회전 금지를 해제한 뒤 새 라인 관측으로 `LINE_TRACK`에 복귀한다.
540 mm 최종 진입 후에는 고정된 두 번의 전진과 넘기를 실행하므로, 카메라 깊이와 발끝 거리를
보정하고 실물 적용 전에 시뮬레이션에서 검증한다.

허들 횟수는 `required_hurdles`(기본 2)와 `hurdles_completed`로 별도 관리합니다.
`GO` 전체의 `SUCCEEDED` 수신 시에만 1회 완료로 집계하며, 중복 상태·실패·대기·준비
미세 전진은 횟수를 올리지 않습니다. 두 번 성공하면 허들 선택만 비활성화하고
기존 판단에 따라 라인·공·골대 주행을 이어갑니다. 공/골대 횟수와 `finish_enabled`는
허들 성공으로 변경되지 않으며, 공/골대 구간이 완료되어도 남은 허들은 실행됩니다.
횟수는 현재 노드 실행 동안 유지되며 노드를 재시작하면 초기화됩니다.

### Lost 제자리 탐색 한도와 슛 후 정렬

슛 후 라인 복귀는 유효한 지면 기준 라인 각도가 **±20도 이내(경계 포함)**일 때
기존 완료 절차를 거쳐 주행한다. 골대 복귀 복합 모션은 우회전 9주기/좌회전 6주기를
포함하며 전체 재생은 한 번이다.

라인·공·골대의 일반 유실 탐색은 마지막으로 본 방향에서 시작한다. 공/슛 처리 후 라인 복귀는
기존 코스별 시작 방향을 유지한다. 허들 근접 회전 금지는 유지한다.

| 단계 | 좌측으로 찾을 때 | 우측으로 찾을 때 | 명령 한도 / 예상 yaw |
| --- | --- | --- | --- |
| 첫 탐색 | 제자리 좌회전 3회 | 제자리 우회전 5회 | 명령 1번 / 45° |
| 같은 방향 추가 탐색 | 좌회전 1회씩 | 우회전 2회씩 | 명령 최대 3번 / 15°씩, 첫 탐색 포함 90° |
| 반대 방향 재탐색 | 우회전 2회씩 | 좌회전 1회씩 | 명령 최대 6번 / 15°씩, 90° |

총 최대 10개 명령이며 절대 회전량 합은 180°다. 보정값 기준 마지막에는 시작 방향으로
돌아오지만, 실제 yaw는 바닥과 자세에 따라 달라질 수 있다. 대상별로 예산과 처음 방향을
따로 유지하며, 중간 후보의 방향 변경만으로 탐색이 처음부터 재시작되지 않는다.
회전 완료·기존 정지 시간·새 관측을 거쳐 다음 명령을 고른다. 원시 검출 후보가 보이면
확정을 기다리고, 일반 유실 탐색은 영상 자체가 없거나 만료되면 회전하지 않는다.
단, 기존 `POST_BALL_LINE_ALIGN`의 입력 부재 탐색 예외는 유지하며 동일한 단계·횟수
한도와 실패 시 중단을 적용한다. 확정된 대상을 따라
유효한 추적 명령을 발행하면 예산을 초기화한다. 모션 실패 또는 한도 소진 후에는 WAIT한다.
실제로 발행한 회전 명령만 예산에서 차감한다. 이미 보이는 대상의 정렬과 필수 슛 후
퇴장 회전은 이 탐색 예산에 포함하지 않는다. 공 집기의 카메라 0° 체크포인트와
일반 공/라인의 45°, 골대의 90° 모션을 각각 유지한다.

`lost_search_max_turns`(기본 3)는 라인·공·골대에서 **같은 방향 추가 탐색 횟수**이며
3을 넘겨도 최대 3번이다. `lost_search_max_angle_deg`(기본 90.0)는 **방향별 한도**이며
최대 90°다. 반대 방향은 최대 6번이다. 횟수 0 또는 각도 45° 미만이면 첫 탐색도 막는다.
허들에는 기존 전체 횟수/누적 각도 제한 의미를 유지한다. 두 launch 모두 같은 이름의
인수를 지원한다. 새 정책은 먼저 시뮬레이션에서 양방향 탐색·재검출·한도 정지를 확인한다.

녹화의 허들 WAIT, 공 소실 시 후진 alias 누락, 두 번째 grab 실패 근거는
[검토 기록](../../artifacts/20260929_goal_loss_review/README.md)에 정리했다.

  모션 완료·1초 정지·새 관측 이후에만 다음 행동을 선택하며 목표 재검출 시 일반 접근으로 복귀한다.
  골대 분석기가 `rgb_stamp_ns`를 전달하고, 유실 시간은 모션 완료/정지 대기 후 첫
  새로운 미검출 프레임부터 시작한다. 판단 함수 호출 간격이나 모션 실행 시간은 더하지 않는다.
  서로 다른 프레임의 촬영·관측 시간이 모두 0.35초를 넘겨야 탐색하며, 중복/역순 프레임은
  시간을 늘리지 않는다. 원시 후보가 다시 보이거나 입력이 만료·중단되면 유실 시간을 초기화한다.
  새 카메라 정보 자체가 없거나 오래되었으면 회전하지 않는다. 골대 미션 잠금 중에는
  8초 경과로 방향 기억을 버리지 않으며, 실행 제한기가 반복 탐색을 제한한다.
- 슛 후 고정 퇴장 회전은 과거 라인 방향을 지우지만, 이후 정렬·전진에서 관측한 방향은
  전진 6회 완료 시에도 보존한다. 중앙에 있는 프레임은 이전의 유효한 좌우 기억을 지우지 않는다.
  화면에는 `LINE LOST | SEARCH LEFT/RIGHT`, `LINE LOST | WAIT`, 탐색 제한 도달 시
  `LINE LOST | SEARCH LIMIT`를 구분한다. 유효한 마지막 방향이 없으면 대기한다.
- 그랩 관찰 도중 임시 결과와 원시 `grab` 상자를 화면에 표시하지 않는다. 검출 데이터와
  기존 40프레임/15회 투표 판정은 그대로 사용한다. 관찰 종료 후 확정된 `GRABBED` 또는
  `NOT GRABBED`만 3초간 표시하고, 새 관찰 시작 시 이전 결과를 숨긴다. `UNKNOWN`은 표시하지 않는다.

### 오프셋 기준점 조향각과 제자리 정렬

`/vision/line_info`의 `offset_reference_x_px`, `offset_reference_y_px`는
`lateral_offset_px`를 계산한 바로 그 라인 기준점이다. 기본 높이는 `image_height * 0.82`다.
`offset_reference_steering_deg`는 보정된 로봇 중심 `(robot_center_x_px, image_height - 1)`에서
이 점을 바라보는 영상 조향각이며, 오른쪽이 양수다.
계산식은 `degrees(atan2(lateral_offset_px, image_height - 1 - offset_reference_y_px))`다.
라인 기울기인 `heading_error_deg`와 다르며, 지면 투영으로 측정한 실제 yaw도 아니다.
기준점이 화면 밖이거나 라인이 소실되면 `offset_reference_valid=false`로 회전을 막는다.

두 full-system launch의 `line_offset_align_enter_px` 기본값은 `-1.0`(자동 정렬 비활성)이다.
실측한 px 기준을 지정하면 일반 라인 추종 중 `abs(lateral_offset_px)`가 그 값을 초과할 때
기준점 조향각으로 `LINE_OFFSET_TURN_LEFT/RIGHT_<count>`를 선택한다.
각도와 추천 횟수는 비활성 상태에서도 `source_command`에 기록한다.
화면의 `Offset steer`에 각도를 표시하고, 정렬 명령 발행 시 기준점·각도·횟수를 로그에 남긴다.

횟수는 기존 제자리 회전 각도표에서 조향각을 넘지 않는 가장 큰 모션으로 고른다.
좌회전은 1/2/3/4/5/6회에 15/30/45/60/75/90도,
우회전은 2/3/5/7/9회에 15/30/45/65/95도다. 최소 모션인 15도 미만이면
기존 recover/전진 판단으로 돌아간다. 회전 완료 후 안정화 대기가 끝난 뒤 촬영한 영상으로
다시 판단하며, 오프셋과 각도가 계속 기준을 초과하면 다시 정렬할 수 있다.
자동 정렬은 우선 로그 재생 또는 시뮬레이션에서 검증하고, 실제 yaw와 영상각의 차이를
확인한 뒤 실물에 적용해야 한다. 공 접근 recover와 line-lost 탐색 정책은 이 설정과 별개다.
