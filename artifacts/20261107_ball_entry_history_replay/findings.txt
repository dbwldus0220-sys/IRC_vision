공 첫 진입: 경계 후보 누적 보존 및 확정 전 관측 재사용

변경 범위
기존 제어 파일은 temporal_confirmation.py, ball_analyzer.py, motion_decision_node.py만 변경했다.
새 보조 파일 ball_entry_candidate_history.py 및 전용 테스트 2개를 추가했다.
모션 JSON, 실행기, 토크 확인, 라인 예약 교체, 미세 접근/줍기/골대 로직은 변경하지 않았다.
기존 10회 확정, 60% 수집/70% 이후 촬영 관측으로 예약 확정, 관측 3개 조건을 유지했다.

경계 예외
기본값은 비활성화이며 BallAnalyzer의 공 확정 필터에서만 활성화한다.
실제 적용은 깊이가 유효하고 거리가 0.6m보다 먼 공의 미확정 트랙에 한한다.
영상 경계 2px 이내에 닿은 상자 쌍의 면적 조건만 실패할 때 검사한다.
중심 이동은 영상 대각선의 최대 5%, 작은 상자의 최소 50%가 겹쳐야 한다.
불확실한 프레임은 hit로 세지 않고 1회만 보류한다.
바로 다음 관측이 원래 상자 또는 보류한 상자와 일치하며 연결 조건을 만족해야 누적을 이어간다.
다음 관측이 없거나 불일치하면 초기화한다. 이미 확정된 트랙에는 예외를 적용하지 않는다.
후보 초기화 때 track_id를 변경해 예약용 거리/방향 기록을 섞지 않는다.
후보를 잘못 연결할 위험을 완전히 없애는 것은 아니며 실주행 검증이 필요하다.

확정 전 관측
실행 중인 라인 모션의 60% 이후 촬영된 후보를 최대 3개 보관한다.
동일 실행 명령/동일 track_id, 유효하고 최신인 깊이/공 지면 방향/검출 상자만 허용한다.
RGB 나이 0.35초, 깊이 나이 0.2초 및 기존 일관성 검사값은 유지한다.
후보 관측으로 실행 명령이나 Ball lock을 만들지 않는다.
첫 확정 입력에서 기록을 한번만 꺼내 같은 공 접근 동작을 지지하는지 다시 검사한다.
최종 확정 프레임을 포함해 3개이며, 최종 촬영 시각은 반드시 모션 70% 이후여야 한다.
방향/후보 번호 변경, 불확실한 공간 일치, 누락/오래된 자료는 재사용하지 않는다.
신규 track_id가 없는 구형 입력은 기존 방식대로 확정 이후 관측을 수집한다.

실제 ROS 그래프, 카메라, 모터를 시작하지 않았다.

변경 전후 비교 (results.json)
기존 로그 기반 합성 입력의 공 확정 조건 10회를 유지했다.
중간 검출 원본이 없어 실제 녹화 전체의 정확한 재생은 아니다.
기본 조건: 공 확정/명령 모두 라인 종료 +134.257ms, 전후 동일. 여전히 대기.
입력 150ms 빠른 조건: 확정 -15.743ms, 명령 0ms(미예약) -> -15.743ms(예약).
입력 300ms 빠른 조건: 확정 -165.743ms, 명령 0ms(미예약) -> -165.743ms(예약).
입력 500ms 빠른 조건: 명령 -171.662ms -> -365.743ms, 모두 예약.
입력 800ms 빠른 조건: 명령 -471.662ms -> -568.703ms, 모두 예약.
마감 16ms 전의 예약은 가짜 전송 환경 결과로, 실제 통신에서 제때 수락될 여유를 보장하지 않는다.

경계 가설 별도 비교 (edge_hypothesis.json)
3회 부분 상자 검출 -> 면적 급변 -> 전체 상자 안정 검출을 가정.
10회 확정에 도달하는 입력 번호가 13 -> 11로 감소했다.
이것은 후보 초기화 원인을 면적 변화로 가정한 검증이며, 실제 영상의 원인을 입증한 결과가 아니다.
국소 10.305 FPS로 환산하면 두 입력 간격은 약 194ms이나 실제 단축 실측은 아니다.
