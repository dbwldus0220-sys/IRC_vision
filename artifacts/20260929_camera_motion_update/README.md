## 반영한 16개 모션

`-64°`는 카메라를 움직이는 **모터의 목표각**이다. 모션 이름의 카메라 자세 `0도`나 로봇의 제자리 회전각을 뜻하지 않는다.

전체 모션 데이터 교체에 함께 포함된 변경:

- 위 좌회전 6개의 두 번째(마지막) 프레임에서 모터 0~22의 `torques`가 모두 `false → true`로 변경되었다. 몸 관절 목표각, 프레임 시간, 반복 횟수는 동일하다.
- `찐미세0도-4`의 프레임 이름과 시작·종료 자세 이름에 `(0도)`가 붙었다.
- 이외 선택된 모션의 변화는 카메라 모터 목표각뿐이다(완료 허용오차 차이 제외).

토크 플래그 변경은 자세 유지/구동에 영향을 줄 수 있다. 실제 로봇에서 실행하지 않았으며, 실기 적용 전 시뮬레이션으로 모션 연결을 확인하고 로봇을 지지한 상태에서 좌회전 마지막 자세와 카메라 시야를 검증해야 한다.

## 다른 차이: 확인만 하고 미반영

아래 회전 횟수는 복합 모션 내부의 회전 프레임 쌍 개수이며, 최상위 `repeat_count`와 구별한다. 기존 데이터에 추가해 둔 회전 구간이 첨부 파일에는 없다. 기존 접두 프레임 데이터는 동일하다.

| 모션 | 현재 런타임 | 첨부 파일 |
|---|---:|---:|
| `찐후진하고 제자리우회전(공)` | 11회 / 24프레임 / 4144ms | 7회 / 16프레임 / 2900ms |
| `찐기본자세에서 제자리 우회전(골대)` | 9회 / 20프레임 / 3531ms | 7회 / 16프레임 / 2907ms |
| `찐기본자세에서 제자리좌회전(골대)` | 6회 / 14프레임 / 2750ms | 4회 / 10프레임 / 2072ms |
| `찐후진에서 제자리좌회전(공)` | 7회 / 16프레임 / 3089ms | 4회 / 10프레임 / 2072ms |

시간은 JSON의 `max_seq_ms`이며 실제 벽시계 실행시간을 뜻하지 않는다. 이전 요청에 따른 골대 우 9회·좌 6회는 유지했다.

`찐골넣기`는 아래 비교 이후 추가 요청에 따라 [최신 첨부 데이터로 반영](../20260929_goal_shot_update/README.md)했다. 완료 허용오차는 5°로 유지했다.

- 두 번째 프레임 `time_ms`: 500 → 600ms.
- 세 번째 프레임 모터 5 목표각: 14 → 12°.
- 세 번째 이후 프레임 시작 시간이 각각 100ms 늦어짐.
- 두 번째 프레임에 편집기 메타데이터 `_drag_original_start_ms: 500` 추가.

우측 라인복귀는 이름에 공백까지 다르다:

- 현재 `찐라인복귀우회전45도(4회)` ↔ 첨부 `찐라인복귀우회전45 도(4회)`.
- 카메라 모터각과 반복 횟수는 같다.
- 세 번째 프레임 모터 11: -1 → 0°, 모터 12: 3.33984375 → -1.66015625°.
- 네 번째 프레임 모터 17: -26 → -24°, 모터 19: 68.115234375 → 67°.
- 첫 프레임 시간: 65 → 60ms, 마지막 프레임 시간: 140 → 130ms. 시작 시각도 변경.
- 네 프레임 모두 모터 0~22 토크 플래그와 `is_important`: false → true.
- 프레임 ID, 일부 자세 이름도 다름. 기존 이름과 `line_recovery_right_4` 매핑을 유지했다.

`찐허들`은 모터각·시간·속도·반복·토크 데이터가 동일하다. `0`과 `0.0` 같은 숫자 표기 및 완료 허용오차 차이만 있다.

## 실행기의 카메라 덮어쓰기

모션 비교 당시 실행기와 두 full_system launch의 `ball_head_override_deg`는 -60.0이었다. 이후 사용자의 추가 요청에 따라 **세 위치의 기본값을 -64.0으로 변경했다.** 실행기의 멤버 초기값도 일치시켰다.

지정된 전진 모션 실행 중 공 검출에서 `head_down_requested=true`가 오면, 기존처럼 400ms에 걸쳐 카메라를 내리고 값을 유지한다. 활성 상태에서는 모션 JSON의 모터 0 목표각보다 이 덮어쓰기 값이 우선한다. `pickup`/`sdk_pickup` 요청에서는 해제한다. 적용 조건과 해제 시점은 그대로다. 사용자가 launch 파라미터를 따로 지정하면 해당 값이 우선한다.

이 변경은 공 덮어쓰기 설정에 한정한다. 허들용 카메라 -60°와 골대용 카메라 1° 설정, 첨부 원본에서 변경되지 않은 다른 모션의 카메라각은 유지했다. 따라서 모든 모션의 모터 0을 일괄 -64°로 만드는 변경은 아니다.
