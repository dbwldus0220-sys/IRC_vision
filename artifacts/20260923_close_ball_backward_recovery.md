# 근접 공 분실 시 1회 후진 복구

픽업 초기/미세 정렬 중 마지막 유효 관측의 bottom_distance_px가 100px 이내이고
새 입력이 detected=False이며 raw 검출도 없으면 회전/전진 탐색 대신 후진한다.
마지막 위치는 픽업 보정 모션 중에도 갱신하며, 나중에 관측한 공이 100px보다
멀면 과거 근접 상태 때문에 후진하지 않는다. 공의 마지막 좌우 방향은 필요 없다.

`BALL_PICKUP_INITIAL_SEARCH_BACKWARD` 또는 `BALL_PICKUP_FINE_SEARCH_BACKWARD`
→ `pickup_lost_ball_backward_1`
→ `후진실전-2(1회, 픽업 카메라0도)`

1회 완료 → 기존 3초 대기 → 새 영상 확인 → 계속 미검출일 때만 다음 1회.
실행 중/대기 중 요청은 추가 후진을 예약하지 않는다. 영상이 없거나 오래되면 대기한다.
raw 검출만 재개돼도 추가 후진을 보류하고 확정된 공 입력으로 기존 정렬을 재개한다.
진행 중인 1회 후진은 도중에 끊지 않는다. 물리적으로 멈추는 최소 단위는 1회다.
실패·취소·시간 초과 시 추가 후진이나 잡기로 진행하지 않는다.
픽업 시작·완료·실패·취소 시 근접 위치 기억을 초기화한다.

## 모션 분리

골대용 후진실전-2(1회)는 원본 후진실전-2(3회)의 repeat_count만 1로 바꾼 항목이다.
이를 복사해 공 복구용 항목을 추가했다. 몸통·다리 각도, 토크, 프레임 시간,
재생 속도, 완료 조건은 동일하고 0번 관절만 -60°로 고정해 카메라 0도 자세를 유지한다.
원본대로면 후진 중 카메라가 약 45도 자세로 올라가 공의 화면 위치가 달라진다.
골대 경로는 기존 별칭/모션과 카메라 override를 유지한다.

기존 카탈로그의 모든 모션을 HEAD와 JSON 객체 단위로 비교했으며 변경은 0개다.
새 항목 1개만 추가했다. 공잡기전후진-2(2회), 공 확인 후 후진실전-2(3회),
골대용 후진실전-2(1회)는 모두 동일하다. 복구 후진은 픽업 고정 시퀀스에 넣지
않으며, 복구 완료 자체를 정렬 완료로 취급하지 않는다. 공 재검출·정렬 완료 후
원래 잡기 전 후진 2회가 별도로 실행된다.

## 검증

플래너·판단 노드·브리지·미션 흐름·카탈로그 계약·영상 표시 테스트:
1,278 passed / 15 failed. 나머지 15개 실패는 변경 전 HEAD를 임시 디렉터리에
풀어 실행했을 때도 동일했다. JUnit 실패 목록을 모듈명/테스트명 기준으로 비교했다.
기존 실패는 골대 0.65m에서 WAIT를 기대하는 테스트 1개와 누락 별칭·모션 이름·
해시 등 카탈로그 기대값 불일치 14개다.

새 후진의 근접 경계, 마지막 관측 갱신, 방향 기억 없음, raw/확정 재검출,
영상 없음, 체크포인트의 이전 프레임 폐기, 중복 요청, 1회씩 재요청,
실패/취소/시간 초과, 정상 잡기 전 후진 보존, 카메라 0도 복사 계약을 검증했다.
실제 로봇은 구동하지 않았다. 실제 적용 전에 시뮬레이션 및 지지 상태에서
꽃게/미세전진 자세에서 새 후진으로 이어지는 연결과 카메라 시야를 확인해야 한다.
