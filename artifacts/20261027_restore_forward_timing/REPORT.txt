전진 시퀀스 타이밍 복원

직전 변경의 문제
JSON 자체의 start_ms/time_ms 값은 그대로였지만, 재생기가 반복 및 다음 전진의 시작 대기 90ms를 생략했다. 4회 전진은 2068ms에서 1798ms로 줄었고, 반복 경계의 목표속도도 연결했다. 프레임 사이(255~345ms)의 별도 90ms 대기는 삭제하지 않았다. 명령 사이의 추가 정지 제거 요청을 저장된 보행 주기 변경으로 확대 적용한 오류다. 보행 이상과의 인과관계는 실측하지 않았으나, 우선 해당 변경을 철회했다.

복원 범위
- RobotMotionPlayer, GuiContinuousTrajectory, motion_pattern, bridge는 직전 전진 연결 변경 전 백업과 일치.
- 반복/예약 경계의 시작 대기를 다시 보존하고, 시퀀스 경계의 속도 연결 제거.
- continuation_group 메타데이터 제거.
- 전진 예측 시간도 517ms * 반복 횟수로 수정.
- 이전부터 제거돼 있던 추가 1초 정지는 재도입하지 않음.
- 전진/라인복귀 1.0배속, 라인복귀 좌우 각각 4회, runtime 허용 오차 5도 유지.
- 원본 R 모션의 프레임 시간과 각도 일치 확인.

검증 파일
build.log: 실행 패키지 빌드
python_tests.log: 카탈로그, 매핑, 영상 수집 시간, 허용 오차 등
cpp_tests.log: 반복 및 예약 시 저장된 90ms 대기 보존, 연속 보간, 가짜 SDK 전송, 독립 수식 대조, queue/backend
실제 모터 구동/토크 변경/노드 재시작은 실행하지 않았다. 실행 중인 노드에는 안전하게 정지한 뒤 재시작해야 복원 코드가 적용된다. 보행 이상이 완전히 해결됐는지는 실제 로봇을 지지한 상태에서 추가 확인이 필요하다.

백업
before_revert.tar.gz는 이번 복원 직전 상태. 직전 연결 변경 이전 원본은 artifacts/20261027_forward_continuation/before.tar.gz. 데이터 전체 복원은 0.9배속/6회 모션도 되돌릴 수 있으므로 이번에는 플레이어 및 연결 코드만 선택 복원했다.
