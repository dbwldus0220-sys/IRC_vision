2026-10-29 일반 모션의 부분 모터 오류 후 경기 진행 복원

요청 범위
position_tolerance_enabled=false로 일부 모터가 응답하지 않아도 경기를 계속
진행하려던 기존 정책을 복원한다. 정상 보간/목표각/배속/미션 판단은 변경하지 않는다.

수정
1. RobotMotionPlayer가 setPositionToleranceEnabled(false)를 받으면 일반 모션
   시작에 부분 모터 오류 허용 경로를 사용한다. ROS의 기존 옵션 전달은 유지한다.
2. 일반 시작 전 토크 OFF/미확인은 ID 오류와 진행 경고를 남기고 프로파일 설정을
   계속한다. 포트 준비 실패/프로파일 송신 실패는 기존처럼 시작을 거절한다.
3. 전체 Present Position 읽기가 실패할 때만 관절별 읽기를 한 번 수행한다.
   새 실측값을 우선하며 누락 관절은 마지막 실측 시작각 또는 마지막 송신 성공
   Goal로 보완한다. 송신 실패 목표는 저장하지 않는다. 응답 복구 시 실측값으로
   복귀한다. 미확인 ID와 initial_fallback trace를 남긴다.
4. 초기화, 시작 자세 도달, cancel, 비상정지의 엄격한 검사는 유지한다.
   전체 무응답이나 누락 관절을 보완할 기준각이 없으면 시작을 거절한다.
   cancel 성공 후에는 hold 이전의 목표 캐시를 비워 다음 시작에서 다시 읽는다.
5. ROS 오류 분류/critical latch는 변경하지 않았다. 부분 모터 문제를 시작
   단계에서 처리하므로 그 이유만으로 HardwareNotReady가 올라가지 않는다.

변경 파일
external_sdk/gui_aligned의 player/hardware/Dxl 및 해당 헤더 7개,
가짜 SDK/기존 하드웨어 테스트 2개, executor README 1개.
원래 작업 중이던 mission_control, motion aliases, JSON 등의 변경은 유지했다.
변경 전체는 changes.patch, 소스와 설치 실행 파일 SHA256은 sha256.json 참조.

사용과 한계
기존 실행 명령의 position_tolerance_enabled:=false를 그대로 사용한다.
다음 노드 실행부터 설치된 코드가 적용된다. 정상 초기화와 필요한 시작 자세
확인을 마친 이후의 일반 모션에 적용되며, 처음부터 모터가 응답하지 않는
토크 초기화 실패를 무시하는 변경은 아니다.
모터가 완전히 응답하지 않는 경우에도 나머지 유효 응답이 있고 기준각이 있어야
시작한다. 관절별 읽기는 실패한 시작에만 발생하지만 그만큼 통신 지연이 늘 수 있다.
이전 목표는 실제 자세를 뜻하지 않으며, 고장 관절의 움직임/균형은 보장하지 않는다.
오류 후 진행 동작은 시뮬레이션에서 먼저 평가해야 한다. 이번 가짜 버스 검증은
동역학 시뮬레이션이 아니며, 실물 보행 안정성을 검증하지 않았다.
