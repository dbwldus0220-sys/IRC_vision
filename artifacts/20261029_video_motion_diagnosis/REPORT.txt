2. 골대 미세전진: 사용자가 정상 GUI 모션을 R미세90도로 확인함
실행 alias goal_camera_90_fine_forward_3 -> r마세90도(3회).
첨부59 JSON의 R미세90도는 현재 runtime에 없다.
r마세90도와 R미세90도는 이름만 다른 동작이 아니다.
- 3번째 프레임(왼발 들기): runtime 55ms, R미세90도 48ms.
- 마지막 프레임 시작: runtime 303ms, R미세90도 296ms.
- 마지막 프레임: runtime r미세오뒤90도, R미세90도는 R미세오뒤90도-1.
- 마지막 자세 ID16: runtime +0.52734375, GUI -1.58203125도.
- 마지막 자세 ID22: runtime -5.712890625, GUI -8.26171875도.
- 전체 차이는 comparison.json에 기록. 양쪽 playback_speed=1.05.
- GUI 원본 repeat=5, 영상에서 실행한 자동 명령 repeat=3.
따라서 사용자가 검증한 모션 데이터가 골대에 들어갔다는 주장은 틀리다.
참고로 runtime은 첨부59의 다른 모션 r마세90도와는 프레임이 같다.
공 접근 r미세0도 또한 첨부59와 프레임 3 시간 및 마지막 자세가 다르다.

5. 검증 및 수정 방향
모터 없는 기존 테스트 268개 중 255 통과, 13 실패.
13 실패는 BALL_FINE_FORWARD_8 다음 전환에서 테스트가 45도 alias를 기대하지만
실제 코드가 0도 alias를 선택하는 기존 불일치. 이번 조사에서 코드 변경 없음.
테스트 통과는 로봇 안정성 검증이 아니다.
수정 우선순위:
- 사용자 확인된 R미세90도 원본으로 골대용 파생 모션 매핑을 교체하고 반복횟수는 분리 검증.
- 공 소실 시 entry.active가 일반 라인 복귀를 영구 가로막는 경로 해소.
  실행 중 모션은 완료시키고 신선한 라인 관측으로 복귀해야 한다.
- 기본자세 전환과 꽃게를 하나의 연결 시퀀스로 검증. 전환을 무조건 삭제하면
  꽃게 시작 지지조건이 달라지므로 임의 제거하지 않는다.
- GUI/자동 속도와 보간 옵션을 하나씩 맞춰 차이를 분리한다.
원본 교체 및 동작 변경은 이번 진단 범위에서 실행하지 않았다.
수정 뒤 시뮬레이션/가상 실행으로 명령 순서를 확인하고, 낙상 방지 지지 상태에서
미세전진 -> 전환 -> 꽃게 전체의 실제 자세/피드백을 확인해야 한다.
